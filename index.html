Scenarios

四种人，同一个需求：别让我手动追版本

如果你的场景和下面任意一条重合，这个工具就是为你写的。

🏠

家庭 NAS / 小主机常开机

为发行版开启订阅并设保留版本数，每次同步自动"刷元数据 → 下最新 N 版 → 删过期"。锁定的文件永远不会被删。

以前：每周手动去镜像站翻目录、比对本地、下载、算哈希、删旧版
🖥️

给 PVE / 装机 U 盘备料

ISO 是要写进系统盘的，来源不可信等于把后门装进宿主。下载后做 SHA256 校验，并对 checksum 文件验 GPG 签名 —— 公钥与硬编码指纹比对，不是"第一次见到就信"。

以前：下完不敢用，只能回官网手动核对哈希
🌐

内网多台机器要取同一批 ISO

起 SMB + WebDAV 只读共享，PVE 直接把 smb://<IP>:1445/iso 加成存储，Windows / macOS 挂 WebDAV。不想开共享，也能点 ⬇ 直接把文件拉回本机（短时票据、支持续传）。

以前：每台机器各下一份，或手搭 Samba 并自己管账号
🧩

清单里没有的发行版 / 内网自建源

自定义源支持任意 ISO 直链，也支持"发行版源"（给个目录地址 + 版本正则，后台自动抓取展开）。独立保存，不会被元数据刷新覆盖。

以前：内置清单没有 = 只能自己 scp 进去，还得手动补校验
Features

为「把 ISO 管明白」这件事而生的能力

从清单浏览到校验落盘，再到局域网共享，一条龙在网页里完成。

📋

发行版清单

聚合主流发行版及其版本、架构、变体，统一浏览。点一次「抓取元数据」就换成镜像站当前的最新版本列表。

⬇️

选择性下载

按版本 / 架构 / 变体勾选，只拉你真正需要的那几个 ISO。勾了整组也能一键全下。

✅

双层校验

SHA256 对清单哈希，GPG 对 checksum 文件验签（覆盖 detached、只签 ISO、内嵌 clearsigned 三种机制）。

🐉

多镜像源容错

每个版本配 2~4 个候选源（清华 TUNA、中科大、阿里云、网易、腾讯、官方兜底），失败自动切换；也可选"实测选最快"。

🔗

自定义源

任意 ISO 直链，或"发行版源"（目录地址 + 版本正则自动展开）。独立文件保存，元数据刷新不会覆盖它。

⭐

订阅同步

设一个保留版本数 N，之后自动"刷元数据 → 下最新 N 版 → 删过期"。可立即执行，也可交给定时任务。

🔒

镜像保护

锁定的文件在清理过期、订阅同步、手动删除时全部硬拒绝 —— 后端连绕过参数都没有。

🌱

种子下载

内置 DistroWatch 官方种子 RSS + 磁力链接 + 自建 RSS，交给 qBittorrent 下载，落盘后与直链统一识别、统一校验。

📡

健康检查与账本

/api/health 报告版本、各挂载点可写性（区分"卷没挂"与"属主不对"）、验签账本；下载完成还能发 SMTP 邮件。

Architecture

Quick Start

三分钟，从零到能下载

需要 Docker 20.10+ 与 Compose v2（docker compose，带空格）。

拉配置并起容器

容器以 uid 10001 非 root 运行，所以挂载目录要先交给它。下面这段国内直连可用。

# 建目录 + 拉 compose（阿里云 ACR 源，国内推荐） mkdir iso-hub && cd iso-hub curl -O https://raw.githubusercontent.com/DC1024/iso-hub/master/docker-compose.acr.yml mkdir -p data backups qb-config webdav-config samba-config sudo chown -R 10001:10001 data backups qb-config webdav-config samba-config docker compose -f docker-compose.acr.yml up -d

播种管理员

公网访问必做。不设的话只允许从本机 / 局域网首次建号（防抢注）。

cat > .env <<'EOF' ISO_HUB_ADMIN_USER=admin ISO_HUB_ADMIN_PASS=换成你的强密码 EOF docker compose -f docker-compose.acr.yml up -d

打开面板，抓一次元数据

访问 http://<服务器IP>:8899 登录，点右上角「⤓ 抓取最新版本元数据」，然后勾选要的版本开始下载。

# 确认服务健康（顺带看版本） curl -s http://127.0.0.1:8899/api/health curl -sI http://127.0.0.1:8899/ | grep -i x-version

要 SMB / WebDAV 共享或种子下载？追加 --profile share / --profile bt。海外服务器把 compose 文件换成 docker-compose.dockerhub.yml。

FAQ

上手前最常问的六个问题

更多排障条目在 Wiki 的常见问题与「已知坑」两篇里。

为什么我起来之后没有「网络共享」和「种子下载」？

它们是可选的 sidecar，挂在 compose profile 下。默认只起 iso-hub + socket-proxy 两个容器；要共享就 --profile share，要种子就 --profile bt。也可以写在 .env 里：COMPOSE_PROFILES=share,bt。

容器启动就退出，日志写「数据目录不可写」？

宿主挂载目录的属主不是 10001。在 compose 目录执行 sudo chown -R 10001:10001 ./data ./backups ./qb-config ./webdav-config ./samba-config 后重启。漏了会立即退出而不是半死不活。

登录报「管理员账号未设置」？

用户表为空且没设 ISO_HUB_ADMIN_USER / ISO_HUB_ADMIN_PASS，此时只允许本机或私有网段建号。在 .env 里播种管理员，或从局域网设备打开面板首次建号。

为什么要把 docker.sock 交给一个代理，而不直接挂？

挂裸 socket 等于把宿主机 root 交给容器里的进程。socket-proxy 用静态白名单只放行"读容器状态 + start/stop/restart"，create / delete / exec 永久 403，切断"应用被攻破 → 起特权容器 → 宿主机 root"这条链。

「刷新列表」和「抓取最新版本元数据」有什么区别？

刷新列表只重读本地清单，不联网；抓取元数据才会联网访问镜像站目录并把最新版本写进清单。前者用于任务结束后刷新展示。

升级会丢数据吗？

不会。所有状态都在宿主机挂载卷里，镜像无状态。docker compose pull && docker compose up -d 即可。唯一要注意的是从 v1.4.x 跨到 v1.5.0+ 必须先 chown 那批目录。升级前想留后路：docker exec iso-hub python /app/scripts/backup.py。
