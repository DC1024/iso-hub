# 贡献指南

这个项目对"改坏了"的容忍度很低：它跑在别人的 NAS 上，管的是别人要写进系统盘的 ISO。
所以下面的规矩不是形式主义，每一条都对应一次真实的返工。

- 想先搞清楚代码怎么组织的 → [项目概览](项目概览)
- 想跑起来看看 → 本篇第 1 节

---

## 1. 本地跑起来

```bash
pip install -r web/requirements.txt -r iso_download/requirements.txt   # Python 3.12+

ISO_DATA_DIR=./data python web/app.py                 # 开发模式，监听 8080
ISO_DATA_DIR=./data python -m waitress web.app:app    # waitress 生产模式
```

`ISO_DATA_DIR` **必须显式指定**。默认值是容器内路径 `/data`，本机跑时不改会被启动自检
直接拒绝（"启动中止: 数据目录不可写"），这是故意的 —— 宁可起不来，也不要"起来了但每次写盘都炸"。

首次启动会在 `./data` 下生成 `settings.json`。未配 `ISO_HUB_ADMIN_USER` / `ISO_HUB_ADMIN_PASS`
时，可从 `127.0.0.1:8080` 建第一个管理员。

## 2. 提交前必跑（与 CI 完全同一套）

```bash
python -m unittest discover -s tests -p "test_*.py"   # 全量回归
python -m ruff check . --select=F                     # 未定义名 / 未使用导入
python -m bandit -r web iso_download scripts -ll      # 只报 Medium 及以上
python -m py_compile web/app.py                       # 语法
```

四条都在 `.github/workflows/` 里跑，本地跑通不等于 CI 一定绿（容器冒烟、CVE 基线、变异测试
是另外三条流水线），但**本地不跑就一定不绿**。

### 2.1 前端改动怎么验

前端是**单文件、无构建、无 lint 工具链**：`web/static/index.html` 里直接写 HTML/CSS/JS，
没有 npm、没有打包、没有 ESLint。`node --check` 只能查语法，查不出"引用了不存在的变量"。

所以：**改了前端就在浏览器里实机点一遍**。这个项目出过的几起"单元测试全绿、浏览器里明显不对"
的问题，全都落在"后端返回了什么"之后的那一层（筛选状态、勾选丢失、表头被隐藏、版本徽标过期）。

最小验证清单：

1. 页面能开、控制台无 `pageerror`；
2. 改动的那个交互走通一次；
3. **刷新一次**，看状态是否还在（很多问题只在刷新后暴露）；
4. 徽标版本号与 `web/version.py` 一致。

## 3. 测试怎么写

### 3.1 这里多数是"契约测试"，不是覆盖率工具

好的契约测试钉的是**"不能退化成什么样"**，而不是"这行代码被执行过"：

```python
def test_sync_does_not_prune_by_dom(self):
    """syncTorrSelUI 不得删除勾选(会按被过滤后的 DOM 误删)"""
    self.assertNotIn("TORR_SEL.delete", self._fn_body("function syncTorrSelUI(){"))
```

它对着一个**具体的历史 bug**：曾经的清理逻辑去看被搜索框过滤后的 DOM，于是未命中的勾选
被当成"已消失"删掉。这条断言保证那段代码不会以任何形式回来。

### 3.2 写测试的三条硬规矩

1. **测试不得破坏生产数据。** 需要在真实 `DATA_DIR` 上跑的东西，一律先 `tempfile` 隔离。
2. **不许改实现去迁就过时测试。** 如果测试失败，先判定是"实现退化"还是"测试过时"。
   测试过时就改测试，并在 docstring 里写清为什么它过时了 —— 但**绝不为了变绿而弱化断言**。
3. **夹具错误 ≠ 代码错误。** 断言之前先确认夹具是对的。
   真实案例：`test_download_status` 曾全线判"未下载"，查到最后是夹具把 classified 布局
   （`DATA_DIR/<类型>/<发行版>/`）写成了 flat 布局（`DATA_DIR/iso/`）—— 代码一行没错。

### 3.3 反向验证

新增的守卫要**证明它有牙**：故意把被测对象改坏，确认测试变红，再恢复。
`scripts/mutation_test.py` 把这件事自动化了一部分（`scripts/mutations.json` 里是变异体）。
一个从不变红的断言，等于没有断言。

## 4. 代码结构上的几条约定

改代码前先看这几条，能省掉一半返工。

### 4.1 内核符号必须"现查"，不能缓存

`app.py` 是内核，`web/api/*.py` 是路由层。路由层拿内核符号的**唯一**通道是：

```python
from api._ctx import core
core.log(...)          # 使用点现查
```

**禁止**：

```python
from app import log    # import 期就把函数对象拷走, patch.object 立刻失效
LOG = core.log         # 模块级快照, 同样失效
```

原因：全仓有 **340 处 `patch.object(app, "log")` 这类打桩**，它们是这个项目唯一有效的故障
注入手段（"磁盘满""qB 掉线""目录不可写"全靠它模拟）。一旦快照化，测试仍绿但桩一次都没打上
—— 比直接报错危险得多。

同理，**内核符号不能在路由模块里当裸名字用**（`log(...)` 而不是 `core.log(...)`）。
这类漏改写只在**请求那一刻**才炸 `NameError` 500，静态检查才拦得住：

```bash
python scripts/check_route_globals.py        # AST 扫内核裸名
python scripts/check_patch_reaches_routes.py # 真实发请求, 断言桩被调到
```

> 探 `check_patch_reaches_routes.py` 的写接口时要**同时关掉鉴权**，否则请求被 401 挡下、
> 视图压根没执行，会被误判成"桩失效"。

### 4.2 异常：能枚举的收窄，真边界才宽捕获

`web/errs.py` 是可预期异常组合的唯一真源（JSON 读写、Docker API、HTTP 请求、qB API 四类）。
新增 `except Exception` 必须在同行写「边界」并给理由，
`tests/test_exception_hygiene.py` 是**只降不升的棘轮**：总数不得超过基线，收窄后要同步调小。

### 4.3 共享 JSON 只走 `config_files.py`

`settings.json` 有多个写方（主进程、`distro_torrents.py`、被 Popen 出的独立进程），
直接 `write_text` 会互相覆盖且**毫无报错**。所有读写走 `config_files.py`，
它提供独立可重入锁 + 原子写（临时文件 + `os.replace`）+ 损坏隔离（备份成 `.corrupt`）。

### 4.4 出站 URL 只走 `url_guard.py`

全站 URL 校验（自定义源、RSS、qB 地址）共用 `url_guard.is_http_url()`。不要另写一份 ——
曾经有三份复制实现，改一侧忘另一侧，表现是"网页上加进去了、后台刷新却被拒"。

### 4.5 版本号只有一处真源

`web/version.py` 的 `__version__`。前端 `index.html` 里的常量只是**首屏兜底**，
必须与它一致（`tests/test_version_consistency.py` 盯着）。发版时同步 git tag
（`vX.Y.Z`）与镜像 tag（`X.Y.Z`，**不带 v 前缀**）。

## 5. 提 PR 的流程

1. **从最新 `master` 切分支**：`git switch -c fix/一句话说明 master`。
2. **一次只改一个功能。** 改 5 个文件同时出 bug，你无法定位是谁的错。
3. **改完立刻运行。** 不运行就继续改，等于在黑暗里叠积木。
4. **跑通立刻提交 Git。** 这样改坏了能一键回到上一个好状态。
5. **推分支，开 PR**。`master` 有分支保护，**直接 push 会被拒**
   （`2 of 2 required status checks are expected`），必须走 PR。
6. 等 `Tests`、`Lint & Security` 两条必需检查变绿。

提交信息参考现有的写法：一句话说清"修了什么现象"和"根因是什么"，需要时在正文里补
"为什么不用另一种改法"。

## 6. 文档改动会被守卫检查

文档不是随便改的，四条测试盯着（都在 `tests/` 下）：

| 守卫 | 检查什么 | 改文档时的意思 |
|---|---|---|
| `test_env_docs.py` | 代码 `os.environ.get("X")` 读过的每个变量，`wiki/` 与仓库根的 `.md` 里必须出现；反向，文档中**反引号包裹**的 `ISO_*` / `QB_*` / `SAMBA_*` / `WEBDAV_*` / `DOCKER_*` / `TZ` / `PUID` / `PGID` 前缀名字必须真实存在 | 提到前端变量时**别给它加反引号**（ISO 开头会被当成环境变量，报"幽灵变量"）；新增环境变量要补进 [环境变量与路径](环境变量与路径) |
| `test_api_docs.py` | 路由装饰器与 `wiki/API.md` 的表格行**双向**对齐 | 加/删路由必须同步改 [API 一览](API) |
| `test_version_consistency.py` | `web/version.py` 是唯一真源：`X.Y.Z` 格式、前端兜底常量一致、`/api/health` 返回 `version`、`GET /` 响应头带 `X-Version` | 升版本时改 `version.py` + `index.html` 兜底常量 |
| `test_wiki_deploy_doc.py` | `wiki/部署-快速开始.md` 里的 ```yaml 代码块必须符合 socket-proxy 与 profiles 约定 | 改部署示例时**不能**让主容器直连裸 `docker.sock`，sidecar 必须挂 profile，且默认只有 2 个容器 |

## 7. 常见返工原因（踩过的）

| 症状 | 真实原因 |
|---|---|
| 测试全绿，但线上功能不对 | 断言写在"后端返回了什么"之前/之后错了一层；或夹具误导 |
| 改了日志/配置不生效 | 用了 `from app import x` 或模块级快照，`patch.object` 打空 |
| 加了 `<thead>` 后筛选就出问题 | 选择器 `.tbl tr` 把表头也匹配进去了，数据行要显式包 `<tbody>` 并收窄选择器 |
| 前端报 `ReferenceError: Cannot access 'X' before initialization` | `let` 声明在脚本靠后，初始化块在靠前访问到了 TDZ |
| 勾选/筛选状态刷新就丢 | 状态只活在内存变量里，没写 `localStorage`；或写进去的 key 被更高优先级的同名 key 顶掉 |
| 改了文档 CI 红 | 撞上第 6 节那四条守卫之一 |
| 下载"没下完就开始校验" | 完整性判据被 `if total and ...` 短路（`total == 0` 时整段核对被跳过） |
| 容器起来了但下载全 500 | 宿主挂载目录属主不是 10001，启动自检没跑到那一步就被绕过 |

## 8. 文档在哪、怎么分工

| 位置 | 定位 | 读者 |
|---|---|---|
| `README.md` | 定位 + 快速上手 + 技术栈 + 目录结构 + 贡献入口 | 第一次访问仓库的人 |
| `wiki/` | 详细功能说明、部署运维、排障 | 已经决定要用、正在部署或排障的人 |
| `gh-pages` 分支的 `index.html` | 宣传站，突出价值与场景 | 还没决定要不要用的人 |

三处**语言风格统一**：中文简体、第二人称、先说结论再说理由、命令可直接复制。
技术名词保留英文原形（Docker、Compose、SMB、WebDAV、GPG），不做生硬翻译。

改完文档，最好顺手确认三处说法没有互相矛盾 —— 尤其是"默认起几个容器"
（答案：**2 个**）与"哪些 sidecar 需要 `--profile`"（samba/webdav → `share`，
qbittorrent → `bt`）。这两条被写错过两次，现在有测试盯着。
