## 1. 一句话定位

**ISO Hub = 上游命令行工具 [Sowevo/iso_download](https://github.com/Sowevo/iso_download) 的网页化 + 服务化封装。**

上游提供的是"能下载"这件事本身：

| 上游文件 | 职责 |
|---|---|
| `iso_download/download_linux.py` | 多源下载、`.part` 原子落盘、断点续传、GPG / SHA256 校验 |
| `iso_download/update_distributions.py` | 抓镜像站目录，生成 `distributions.json` 清单 |
| `iso_download/distributions.json` | 随包分发的样例清单 |
| `iso_download/sources_config.json` | 镜像源定义（清华 TUNA、中科大 USTC 等） |
| `iso_download/torrent_categories.json` | 种子分类规则 |

它缺的是"用起来"这件事：改配置要开编辑器、发起下载要敲命令、看进度盯终端、删旧版记得住、
多台机器取文件得自己搭共享。

本项目**不重写下载器**，而是在它外面加一层：

```text
上游 CLI（下载/校验，只读、保持可替换）
        ↑ 以 subprocess 调用，命令以 list 传参（不做字符串 split）
Web 层（Flask + 单文件前端）
        ↑ 提供勾选、进度、订阅、定时、共享、健康检查
Docker（默认 2 容器 + 2 个可选 sidecar）
```

**边界很清楚**：上游脚本目录 `iso_download/` 在本项目里保持"只读、不可变"，页面上的所有能力
都是 Web 层在其上编排的结果。这也是为什么升级上游脚本是一件独立、可控的事
（见 [升级上游脚本](升级上游脚本)）。

## 2. 使用场景

### 场景 A：NAS 自己追新版 ISO

以前：每周手动去清华镜像站翻目录，比对本地有哪些版本，下载、比对哈希、删旧版。
现在：为发行版开启**订阅**并设保留版本数 N，交给内置调度器。每次同步自动
"刷元数据 → 下最新 N 版 → 删过期"，🔒 锁定的文件不会被删。

→ [订阅同步](订阅同步)

### 场景 B：给 PVE / 装机 U 盘备料，且要能证明文件是干净的

ISO 是要写进系统盘的，来源不可信等于把后门装进宿主。
本项目在下载后做**双层校验**：清单里的 SHA256，加上对 `checksum` 文件的 **GPG 签名**验证 ——
公钥从官网 HTTPS 取回后与代码里硬编码的指纹比对，避免了"第一次见到的公钥就信"（TOFU）。
三种签名机制都覆盖：Ubuntu 式 detached 签名、Arch 式只签 ISO、Fedora 式内嵌 clearsigned。

→ [下载与元数据](下载与元数据)

### 场景 C：内网多台机器要取同一批 ISO

以前：要么每台机器各自下载（重复占带宽），要么手搭 Samba 并自己管账号。
现在：`--profile share` 起 SMB + WebDAV 两个只读共享 sidecar，PVE 直接把
`smb://<IP>:1445/iso` 加成存储，Windows / macOS 挂 WebDAV。
不想开共享？镜像列表里点 ⬇ 也能把文件直接拉到当前浏览器（短时票据 + 断点续传）。

→ [网络共享（SMB / WebDAV）](网络共享-SMB-WebDAV)

### 场景 D：清单里没有的发行版 / 内网自建镜像

Kali、某个 LTS 的特定小版本、公司内网的 ISO 仓库 —— 内置清单不可能全覆盖。
**自定义源**支持两种形态：任意 ISO 直链，或"发行版源"（给一个目录地址 + 版本正则，
后台自动抓取展开）。自定义源独立保存在 `custom_sources.json`，**不会被元数据刷新覆盖**。

→ [自定义源](自定义源)

### 场景 E：官方站点只发种子

部分发行版（尤其是新版本首发）只给 torrent。**种子下载**内置 DistroWatch 官方种子 RSS，
也可以手动粘磁力链接、加自建 RSS 源；交给 qBittorrent 下完后，文件落在同一批目录，
与直链下载的 ISO 统一识别、统一校验、统一共享。

→ [种子下载](种子下载)

## 3. 核心功能全景

比 README 的功能表更细，每条都对应页面上真实存在的能力。

### 3.1 镜像列表（主界面）

- 按**发行版分组**展示，可折叠；组内按版本、架构、变体排列。
- 统计条：发行版组数 / 清单文件数 / 本地已占空间 / 元数据更新时间。
- 筛选：全部 / 已下载 / 未下载 / 已收藏（筛选值持久化，刷新后回填到下拉框）。
- 每行：★ 收藏、🔒 锁定、勾选框（可整组勾选）、状态徽标、镜像源下拉、行内 ⬇ / 🗑。
- 状态是**五态**：已下载 / 下载中 / 下载停止（可续传）/ 下载失败（需重下）/ 未下载。
- 勾选跨筛选保留（以 `download_url` 为 key）；删除/下载等动作只对**可见行**生效。

### 3.2 下载与校验

- 勾选后「⬇ 下载所选」，后台任务线程执行，顶部任务条实时显示进度、速率、当前文件。
- 下载期间写 `<最终名>.part`，**只有大小校验 + 哈希校验都通过才 `os.replace` 成正式名** ——
  残缺文件不可能以正式文件名出现在磁盘上。
- 支持 HTTP Range 续传；服务器不支持 Range（返回 200）时会明确告警并从头下载。
- **写第一个字节前先查剩余空间**，不足直接拒单（不产生半成品、不换源重试）。
- 校验源不可达但长度达标时，文件标 **⚠ 未验签**（可用但无证据）；后续可点 **⟳ 重新校验**，
  只读盘算哈希，不必重下几个 GB。

### 3.3 元数据刷新

- 「⤓ 抓取最新版本元数据」联网抓镜像站目录，写入 `distributions.json`（默认每组保留最新 3 个）。
- 「🔄 刷新列表」只重读本地清单，**不联网** —— 这两个按钮是不同概念，容易混。
- 镜像站失效比例达到阈值时 `/api/health` 会升级为 error 级别，避免"大规模异常但页面一切正常"。

### 3.4 订阅同步与定时任务

- 为发行版开启订阅 + 设保留版本数 N → 每次同步"刷元数据 → 下最新 N 版 → 删过期旧版"。
- 内置调度器按 `ISO_HUB_SYNC_INTERVAL`（默认 86400 秒）自动跑，设 `0` 关闭。
- 网页可另建定时任务：每天 / 每周 / 每月 / 每年 / 一次性；`type` 走白名单、`time` 走
  `HH:MM` 正则校验，非法入参**一律 400 且不落盘**（存进去但永不触发是最坏的结果）。

### 3.5 自定义源

- 两种条目：普通直链、发行版源（`listing_url` + strategy）。
- 发行版源的展开走**持久化缓存 + 后台子进程**，请求线程内绝不发网络请求 ——
  否则一个慢站就能占满 waitress 线程、把全站拖死。
- 支持手动「🔄 刷新发行版源」与自动定时刷新（默认关闭，间隔默认 86400 秒，最小 60）。

### 3.6 种子下载

- 三个子标签：种子源（官方列表 / magnet / RSS）/ 下载列表（含全部、下载中、已完成、做种筛选）/ 分类管理。
- 内置 6 个预置分类（Ubuntu / Debian / Arch / Fedora 系 / Proxmox / 工具盘），
  未命中进「未分类」并固定排最后；预置分类**只能禁用不能删除**，可另加自定义分类。
- 匹配语义刻意区分：**关键词按词首**匹配（`ubuntu` 覆盖 `ubuntukylin`），
  **排除词按完整词**匹配（`arch` 不误伤 `search`）。
- 支持内置 qBittorrent sidecar，也支持填外部 qB 实例（此时不碰任何容器，只走 Web API 登录）。

### 3.7 管理、安全与运维

- **单管理员**登录（PBKDF2-SHA256），会话存 `settings.json`；登录失败不区分"用户名不存在"
  与"密码错误"（统一 `bad_credentials`），避免把登录接口变成账号枚举机。
- **镜像保护 🔒**：锁定文件在清理、订阅同步、手动删除时被**硬拒绝**（后端已移除 `force` 绕过参数）。
- **附加访问令牌** `ISO_HUB_TOKEN`：所有写操作需携带。
- **健康检查** `/api/health`：版本、各挂载点可写性四态、服务状态、GPG 验签账本
  （含 `stale` —— 只统计当前真在盘上的文件，删了的不再虚高）。
- **备份 / 恢复**：`docker exec iso-hub python /app/scripts/backup.py` 打包四个 JSON 状态文件。
- **邮件通知**：下载 / 订阅同步完成后可发 SMTP 邮件（465/SSL），默认关闭，密码不回传前端。
- **可选静态加密**：设 `ISO_HUB_SECRET_KEY` 后 `settings.json` 整文件 AES-GCM 落盘。

## 4. 技术栈

| 层次 | 选型 | 版本 / 形态 | 为什么 |
|---|---|---|---|
| 运行时 | Python | **3.12.15**（`python:3.12.15-slim`，tag + digest 双钉） | 浮动 tag 会让同一 commit 两次构建产物不同，无法复现也无法对比 CVE |
| Web 框架 | Flask | **3.1.3** | 体量匹配：这是个单管理员、单进程、无 ORM 的工具，不需要更重的框架 |
| WSGI | waitress | **3.0.2** | 纯 Python 多线程，单容器内够用；不引入 gunicorn 的 preload/worker 复杂度 |
| 前端 | 原生 HTML / CSS / JS | **单文件 `web/static/index.html`** | 零构建、零 npm、零 node_modules；后端给什么就渲染什么 |
| XML | defusedxml | **0.7.1** | 解析镜像站 / RSS 的 XML，防实体膨胀 |
| 加密 | cryptography | **50.0.2** | `settings.json` 可选 AES-GCM；缺密钥时**懒加载**，不设就完全不 import |
| 下载 / HTTP | requests、tqdm | 随上游 CLI | 上游依赖，`constraints.txt` 钉死版本 |
| 签名校验 | gnupg / gpgv（apt） | Debian 包 | 系统 gpg，比 Python 绑定更贴近上游 checksum 的实际用法 |
| 容器 | Docker + Compose v2 | profiles 管 sidecar | v1 的 `docker-compose` 不支持 profiles 且已 EOL |
| Docker API 代理 | haproxy | **2.8-alpine**（钉 digest） | 上游 socket-proxy 只能按"方法 + 路径前缀"放行，做不到"读状态 + 只许 start/stop" |
| 持久化 | 纯 JSON 文件 | `settings.json` 等 | 无数据库：备份就是拷几个文件，恢复就是放回去 |
| 测试 | unittest | 58 个测试文件 | 标准库，CI 零额外依赖；大量"契约测试"防退化 |
| 静态检查 | ruff `--select=F`、bandit `-ll`、py_compile | — | 只报真问题：未定义名、未使用导入、Medium 以上安全问题 |

依赖可复现的做法见 `constraints.txt` 文件头：`requirements.txt` 里全是 `>=`（下限而非锁定），
`constraints.txt` 把**生产实测版本**钉死，再由 `tests/test_supply_chain.py` 防止被改回去。

## 5. 架构

```text
                     ┌──────────────────────────────┐
   浏览器  ──────────▶ │  iso-hub（Flask + waitress）   │
   (Web UI / API)     │  uid 10001 · 根文件系统只读    │
                     └───┬───────────┬──────────┬───┘
                         │           │          │
             Docker API  │           │ HTTP     │ subprocess
                         ▼           ▼          ▼
              ┌──────────────┐  ┌─────────┐  ┌──────────────────┐
              │ socket-proxy │  │ 镜像站   │  │ 上游 CLI          │
              │ (haproxy)    │  │ TUNA 等  │  │ download_linux.py│
              │ 静态白名单    │  └─────────┘  └────────┬─────────┘
              └──────┬───────┘                          │
                     │ 只放行 GET /containers/*          │ 写 .part → 校验 → rename
                     │ 与 POST .../(start|stop|restart)  ▼
                     ▼                          ┌──────────────┐
              ┌──────────────┐                  │  ./data      │
              │ docker.sock  │                  │  linux/<发行版>│
              └──────────────┘                  └──────┬───────┘
                                                     │ 只读挂载
                                    ┌────────────────┴────────────┐
                                    ▼                             ▼
                            ┌──────────────┐              ┌──────────────┐
                            │ samba        │              │ webdav       │
                            │ profile:share│              │ profile:share│
                            └──────────────┘              └──────────────┘
```

**默认只有 2 个容器**（`iso-hub` + `socket-proxy`）。samba / webdav 归 `share` profile、
qbittorrent 归 `bt` profile，**不带 `--profile` 就不会创建、不会拉镜像**。

### 5.1 为什么主容器不挂裸 `docker.sock`

挂裸 socket 等于把宿主机 root 交给容器里的进程。改为经 socket-proxy 按**静态白名单**转发：
只放行 `GET /containers/*` 与 `POST .../(start|stop|restart|update)`，
**create / delete / exec 永久 403** —— 切断"应用被攻破 → 起特权容器 → 宿主机 root"这条链。

没挂 socket 时面板不会"坏了"，而是**降级**：容器状态显示为未知，SMB / qB 的启停按钮不可用，
但下载、校验、订阅、共享配置全都照常工作。降级细节见
[部署 · 快速开始](部署-快速开始) 的「关于 Docker 权限」。

### 5.2 一次下载的完整路径

```text
① 前端勾选 → POST /api/download（携带 X-Auth-Token）
② 后端查剩余空间（不足直接 400，不产生半成品）
③ 起后台任务线程 → subprocess 调上游 CLI（命令以 list 传参）
④ CLI 边下边打 #TARGET <path> <bytes> 哨兵 → 后端据此算进度
⑤ 写 <最终名>.part（断点续传走 Range）
⑥ 长度达标 → 查清单 SHA256 → 有 checksum 文件则验 GPG 签名（公钥指纹比对）
⑦ 全部通过 → os.replace 改成正式名；不通过 → 按"截断/损坏/未知"分别处理
⑧ 前端 5 秒轮询 /api/state → 进度条推进；结束后自动刷新列表
```

第 ⑦ 步的区分很重要：**截断**保留 `.part` 供续传，**内容损坏**丢弃重下，
**长度未知且校验不过**保守保留 —— 宁可多占磁盘，也不误删用户几百 MB 的进度。

## 7. 它明确**不**做的事

把边界写清楚，比列一堆功能更能说明定位：

| 不做 | 原因 |
|---|---|
| 不提供 PXE / 网络启动 | 那是 dnsmasq + TFTP 的活，和"管 ISO 文件"是两件事 |
| 不做镜像站反向代理 | 下载是直连镜像站，本项目只负责"选源"和"校验" |
| 不是多租户系统 | 单管理员设计；需要多人分权请在前面套一层反代 + 认证 |
| 不管理 U 盘 / 刻录 | 只到"文件可信地躺在磁盘上"为止 |
| 不内建 TLS | 请用反向代理终止 HTTPS，并设 `ISO_HUB_TRUST_PROXY=1` |
| 不自动清理未锁定之外的一切 | 删除动作都要显式触发，订阅同步只删"超出保留版本数"的那些 |
