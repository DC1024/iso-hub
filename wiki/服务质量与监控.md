# 服务质量与监控

> 本页介绍 ISO Hub 服务的质量保障机制和运行监控，帮助用户了解服务的可靠性和如何排查问题。

## 服务质量保障

### 1. 多重校验机制

ISO Hub 提供三重数据完整性校验，确保下载的 ISO 镜像安全可靠：

#### SHA256 校验
- **作用**：验证文件完整性，防止传输损坏
- **机制**：下载完成后自动计算 SHA256 并与官方校验和比对
- **覆盖范围**：所有 ISO 文件

#### GPG 签名验证（支持发行版）
- **作用**：验证校验和文件的官方签名，防止清单被篡改
- **支持的发行版**：
  - Ubuntu：detached 签名模式
  - Arch Linux：仅对 ISO 文件签名
  - Fedora：内嵌 clearsigned 签名
- **验证流程**：
  1. 从官网获取官方公钥（HTTPS）
  2. 与硬编码的指纹锚定（防止 TOFU 风险）
  3. 使用 gpgv 验证签名

#### 校验和文件验证
- **作用**：确保 SHA256 清单文件的完整性
- **机制**：通过 GPG 验证确保校验和清单未被篡改

### 2. 下载容错机制

#### 自动重试
- 网络中断时自动重试（最多 3 次）
- 支持断点续传（保留 `.part` 文件）

#### 多源切换
- 自动检测最快的镜像源
- 主源失败时自动切换备用源

#### 进度保护
- 下载中断时保留进度文件
- 支持从断点继续下载

### 3. 数据一致性保证

#### 配置同步
- Web 界面配置实时同步到后端
- 配置更改立即生效，无需重启

#### 状态一致性
- 下载状态、文件状态实时更新
- 避免界面显示与实际状态不一致

## 运行监控

### 1. 健康检查

#### 服务健康状态
- **检查端点**：`http://<IP>:8899/api/health`
- **正常响应**：
  ```json
  {
    "ok": true,
    "gpg_ledger": {
      "configured": true,
      "states": {"pass": 5, "fail": 1, "skip": 3},
      "never_invoked": []
    }
  }
  ```

#### GPG 验证监控
- **监控内容**：
  - `pass` - GPG 验证通过
  - `fail` - GPG 验证失败
  - `skip` - 跳过 GPG 验证（无签名）
  - `never_invoked` - 从未获得验证机会
- **意义**：确保 GPG 验证真正执行，而非仅代码接入

### 2. 自动监控机制

#### 端点可用性监控
- **监控频率**：每 6 小时自动检查
- **监控端点**：
  - `/api/health` - 服务健康状态
  - `/api/distros` - 发行版列表
  - `/api/subscriptions` - 订阅状态
- **告警机制**：
  - 少量失效（<30%）：警告通知
  - 大量失效（>30%）：紧急告警

#### 容器自愈能力
- **故障检测**：自动检测容器异常状态
- **自动重启**：容器故障时自动重启恢复
- **状态同步**：重启后自动同步配置状态

## 用户可用的诊断工具

### 1. 基本检查命令

#### 检查服务状态
```bash
# 检查容器运行状态
docker ps | grep iso-hub

# 检查服务健康状态
curl http://localhost:8899/api/health

# 检查端口占用
netstat -tlnp | grep 8899
```

#### 检查日志信息
```bash
# 查看最新日志
docker logs iso-hub --tail 100

# 查看错误日志
docker logs iso-hub --tail 100 | grep ERROR

# 实时监控日志
docker logs -f iso-hub
```

### 2. 下载状态诊断

#### 检查下载进度
```bash
# 查看下载中的文件
ls -la /data/downloads/

# 检查 .part 文件（断点续传）
ls -la /data/downloads/*.part

# 查看磁盘使用情况
df -h /data
```

#### 验证下载文件
```bash
# 检查 ISO 文件完整性
file /data/downloads/*.iso

# 验证 SHA256 校验和
sha256sum /data/downloads/*.iso
```

### 3. 网络连接诊断

#### 检查网络连通性
```bash
# 测试到镜像站的连接
curl -I https://mirrors.tuna.tsinghua.edu.cn/

# 检查 DNS 解析
nslookup mirrors.tuna.tsinghua.edu.cn

# 测试端口访问
telnet <IP> 8899
```

## 常见问题排查

### 1. 服务无法访问

#### 可能原因
- 容器未运行
- 端口被占用
- 防火墙阻止
- 网络配置问题

#### 排查步骤
1. 检查容器状态：
   ```bash
   docker ps | grep iso-hub
   ```
2. 检查端口占用：
   ```bash
   netstat -tlnp | grep 8899
   ```
3. 检查防火墙：
   ```bash
   # Linux
   sudo ufw status
   # Windows
   netsh advfirewall show allprofiles
   ```
4. 测试本地访问：
   ```bash
   curl http://localhost:8899/api/health
   ```

### 2. 下载失败或缓慢

#### 可能原因
- 网络连接问题
- 镜像源不可用
- 磁盘空间不足
- 容器资源限制

#### 排查步骤
1. 检查网络连接：
   ```bash
   curl -I https://mirrors.tuna.tsinghua.edu.cn/
   ```
2. 检查磁盘空间：
   ```bash
   df -h /data
   ```
3. 检查容器资源：
   ```bash
   docker stats iso-hub
   ```
4. 查看下载日志：
   ```bash
   docker logs iso-hub --tail 50 | grep download
   ```

### 3. GPG 验证失败

#### 可能原因
- 校验和文件格式问题
- GPG 公钥过期
- 签名文件损坏

#### 排查步骤
1. 检查 GPG 状态：
   ```bash
   curl http://localhost:8899/api/health | jq '.gpg_ledger'
   ```
2. 查看验证日志：
   ```bash
   docker logs iso-hub --tail 20 | grep gpg
   ```
3. 手动验证（可选）：
   ```bash
   # 进入容器
   docker exec -it iso-hub bash
   
   # 手动验证
   gpgv --keyring /app/keys/public.gpg /path/to/checksums /path/to/ISO
   ```

### 4. 配置问题

#### 可能原因
- 配置文件权限问题
- 环境变量设置错误
- 数据目录不可写

#### 排查步骤
1. 检查数据目录：
   ```bash
   ls -la /data/
   ```
2. 检查配置文件：
   ```bash
   cat /data/settings.json | jq .   # 未设 ISO_HUB_SECRET_KEY 时是明文 JSON
   ```
   > ⚠️ **若设置了 `ISO_HUB_SECRET_KEY`**：`settings.json` 已被 AES-GCM 整文件加密，直接 `cat` 会看到二进制密文（以 `ISOHUB-SETTINGS-ENC-v1` 开头）而不是 JSON。此时不要手工改它——用面板改设置即可（应用会自动解密/重加密）。解密/加密逻辑在 `web/config_files.py`。
3. 检查环境变量：
   ```bash
   docker inspect iso-hub | grep ENV
   ```

## 性能优化建议

### 1. 网络优化

#### 使用国内镜像源
- 推荐使用清华、中科大等国内镜像源
- 在「自定义源」中配置国内加速地址

#### 网络配置
- 确保主机与容器间网络通畅
- 避免使用代理（除非必要）

### 2. 存储优化

#### 磁盘空间管理
- 定期清理过期的 ISO 文件
- 使用「清理过期」功能自动清理旧版本

#### 数据目录配置
- 将数据目录放在高速存储设备上
- 确保有足够的磁盘空间（建议至少 50GB）

### 3. 容器优化

#### 资源限制
- 根据实际需求调整 CPU 和内存限制
- 监控容器资源使用情况

#### 定期维护
- 定期更新镜像到最新版本
- 定期检查日志文件大小
