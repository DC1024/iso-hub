# 常见问题与避坑指南

本页记录 ISO Hub 使用中可能遇到的问题和解决方案，帮助用户快速排查和解决问题。

## 部署 / 网络相关

### 服务器原生 Samba 占用 445 → 容器 Samba 用高位端口

- 极空间 Z4Pro 自带 Samba 占用 445/139/137/138，容器版 Samba 映射到 **1445/1139/1137/1138**。
- 客户端访问要按实际映射端口填。

### 暴露公网，别忘了防火墙

- 腾讯云 Lighthouse/轻量：默认只放行 22/80，**其他端口（8899/1445/8081）需在控制台安全组放行**。
- 容器内验证：`curl http://localhost:8899/api/health`；公网验证：从别的机器 `nc -vz <IP> 8899`。

### 下载报错：`unrecognized arguments: "Arch", "download_url": ...`

**已修复（1.0.1+）**。这是旧版 bug：后端把命令拼成字符串后 `.split(" ")` 拆分，把带空格/逗号/引号的 JSON `--select` 参数拆坏成多个 argv，导致 argparse 报 unrecognized arguments。

- 现象：`iso_runner.py: error: unrecognized arguments: "Arch", "download_url": ...`
- 修复：命令以 **list** 传给 `subprocess.Popen`（不再字符串 split）。
- 解决：**升级到最新版本**（docker compose 重建）即可。

### 日间模式，任务日志部分文字看不清（颜色接近背景）

**已修复（1.0.0+）**。原因：日志面板背景固定深色，但普通 `<pre>` 文本继承了日间主题的深色 `--ink`，深字配深底看不清；夜间主题 `--ink` 是浅色所以正常。

- 修复：日志区内文本改为固定浅色（`#cbe3ff` / `#d7e7ff` / 时间戳 `#8fb6dd`），不再依赖主题变量。
- 若仍看不清：强制刷新（Ctrl+F5）确保加载新前端（看标题徽章版本号）。

### 下载没进度条

**已修复（1.0.1+）**。原因：后端 `/api/state` 的下载项缺少 `total` 字段，前端无法算百分比。

- 修复：下载前先 HEAD 探测目标文件大小（`#TARGET <path> <bytes>`），写入任务的 targets 映射，`running_task()` 据此给每项加 `total`，前端渲染进度条百分比。

### 进度条卡在 0%，日志只在「停止任务」后才刷出

**已修复（1.0.2），本坑极隐蔽，务必升级。** 

根因不是后端，而是**前端变量遮蔽**：`poll()` 里 `const t = s.task` 用局部变量 `t` **遮蔽了全局 i18n 翻译函数 `t()`**。后续 `t('taskMeta')` / `t('curPrefix')` 抛 `TypeError: t is not a function`，被外层 try/catch 静默吞掉 → 任务类型/当前文件/进度条全不更新；`fetchLogs()` 也被跳过，所以日志只有走「停止任务」else 分支时才刷出。

- 修复：poll() 内局部变量 `t` 改名 `tk`；同时修了 `applySrcTpl()` 里同样的遮蔽。
- 升级到 **1.0.2+** 后，实机验证进度条正常 2%→4%→…持续增长。

### 点「刷新列表」没反应，且分不清它和「抓取最新版本元数据」的区别

这是两个不同概念，都不是 bug：

- **刷新列表**：只**重读本地** `distributions.json` 到界面，**不联网**。用于后台任务完成后刷新展示。
- **抓取最新版本元数据**：**联网**访问清华镜像站，把**最新版本**写进清单（默认每组留最新 3 个）后再刷新列表。

若点「刷新列表」确实毫无反应：大概率是浏览器缓存了旧前端（徽章版本号偏旧）。**强制刷新**（Ctrl+F5）。

### 顶部有两个「网络共享」，重复

**已修复（1.0.3）**。1.0.3 起删除顶部独立的「网络共享」标签页，网络共享统一并入**「设置 → 共享设置」**。功能一致（同一 `/api/shares` 后端）。

## 使用相关

### 下载中断后文件显示"下载停止"但无法删除

- 现象：下载中断后，文件状态显示"下载停止（可续传）"，但点击删除按钮没有反应。
- 解决：确保文件没有被其他进程占用，可以重启容器后重试删除：
  ```bash
  # 重启容器
  docker restart iso-hub
  
  # 然后尝试删除
  # 通过 Web 界面删除或手动删除文件
  rm /data/downloads/*.part
  ```

### GPG 验证失败但 SHA256 校验通过

- 现象：文件下载完成，SHA256 校验通过，但 GPG 验证失败。
- 可能原因：
  1. 该发行版版本没有 GPG 签名（某些版本可能不提供）
  2. 校验和文件格式问题
  3. GPG 公钥过期
- 解决方案：
  1. 检查发行版是否提供 GPG 签名
  2. 查看详细错误日志
  3. 如果确认无签名，可以跳过 GPG 验证（仅依赖 SHA256）

### 订阅同步时进度条卡在 50%

- 现象：执行订阅同步时，进度条一直显示 50% 不动。
- 可能原因：
  1. 网络连接问题
  2. 镜像源响应缓慢
  3. 磁盘空间不足
- 解决方案：
  1. 检查网络连接
  2. 确保有足够的磁盘空间
  3. 查看同步日志获取详细信息

### Web 界面显示"请先登录"但实际已登录

- 现象：操作时提示"请先登录"，但实际已经登录。
- 可能原因：
  1. 浏览器缓存问题
  2. 会话过期
- 解决方案：
  1. 强制刷新页面（Ctrl+F5）
  2. 清除浏览器缓存和 Cookie
  3. 重新登录

### 自定义源无法解析出 ISO 文件

- 现象：配置自定义源后，点击"抓取最新版本元数据"无法解析出 ISO 文件。
- 可能原因：
  1. 源格式不符合要求
  2. 正则表达式错误
  3. 网络连接问题
- 解决方案：
  1. 检查源地址是否正确
  2. 验证正则表达式语法
  3. 确保网络可以访问源地址

### 下载速度缓慢

- 现象：下载速度远低于预期。
- 可能原因：
  1. 网络带宽限制
  2. 镜像源服务器负载高
  3. 容器资源限制
- 优化方案：
  1. 使用国内镜像源
  2. 配置多个备用源
  3. 调整容器资源限制
  4. 在网络空闲时段下载

### 磁盘空间不足

- 现象：下载失败，提示磁盘空间不足。
- 解决方案：
  1. 清理过期 ISO 文件（使用"清理过期"功能）
  2. 扩大数据目录空间
  3. 定期清理不需要的文件

### 网页能开，但下载/操作没权限提示

检查是否触发了登录/令牌门禁：

1. 检查是否已登录：界面右上角显示用户名
2. 检查环境变量：`.env` 文件是否设置了 `ISO_HUB_ADMIN_USER` 和 `ISO_HUB_ADMIN_PASS`
3. 公网部署：首次使用需要先创建管理员账户

## 安全相关

### 开了 settings.json 加密后，密钥必须一直留着

- 现象：设了 `ISO_HUB_SECRET_KEY`、跑了一阵后有人把 `.env` 里的密钥删了 / 容器环境变量清掉 → 重启后面板打不开或设置全丢。
- 根因：文件已是 AES-GCM 密文，缺密钥解不开；应用会把该文件当损坏，且下次写入可能把它重置成空配置（**不可逆的数据丢失**）。
- 预防 / 解决：
  1. 密钥当作"和数据库密码同级"的资产单独备份，别随手删 `.env` 这一行。
  2. 换密钥前先备份 `data/settings.json`（旧密钥仍可读时导出）。
  3. 密钥丢了只能从备份还原；没有备份基本等于设置全丢。但 ISO 文件、发行版清单、订阅配置等不依赖 settings，不受影响。
- 详见「环境变量与路径」的 *settings.json 静态加密* 一节。

### chmod 600 挡不住 root 读者

`settings.json` 写入后 `chmod 600`，但容器以 root 运行，这条只能挡"非 root 读者"。真正的静态保护是 AES-GCM 加密 + 密钥不放进 data 卷；别把 `ISO_HUB_SECRET_KEY` 写进挂载到 `/data` 的文件里。

## 前端 / 界面相关

### 浏览器缓存导致界面不更新

- 现象：更新了 ISO Hub 但界面还是旧版本。
- 解决：
  1. 强制刷新页面（Ctrl+F5）
  2. 清除浏览器缓存
  3. 检查界面右上角的版本号

### 进度条显示异常

- 现象：下载进度条不动或显示不正确。
- 可能原因：
  1. 浏览器兼容性问题
  2. 网络连接问题
- 解决：
  1. 尝试使用不同浏览器
  2. 检查网络连接
  3. 查看容器日志

### 界面元素错位

- 现象：页面布局混乱，按钮重叠等。
- 解决：
  1. 确保浏览器窗口大小合适
  2. 尝试缩放页面（Ctrl+/-）
  3. 清除浏览器缓存后重试

## 数据管理

### ISO 文件损坏

- 现象：下载的 ISO 文件无法使用。
- 解决：
  1. 重新下载（系统会自动清理损坏文件）
  2. 检查 SHA256 校验和
  3. 验证 GPG 签名（如果支持）

### 重复下载相同版本

- 现象：同一个版本被多次下载。
- 解决：
  1. 使用"清理过期"功能删除旧版本
  2. 在下载前检查是否已存在
  3. 启用"自动清理"选项

### 修复"ISO 还没下完就开始校验"

**已修复（1.2.9+）**。现象是日志里下载 19:45 开始、19:47 就报 `✗ 校验和验证失败, 丢弃半成品重试`——一个 1523 MiB 的文件只下了 56 MiB 就去算校验和，必然失败。

- 根因：服务器**没有返回 `Content-Length`**（或其非法/为 0）时 `total == 0`，整个大小核对被 `if total and ...` 静默跳过，不完整的文件就直接进入 SHA256 比对 → 必然不符。
- 修复：**长度三级兜底**（`Content-Range` 全长 > `Content-Length + 已下量` > 调用方 HEAD 预取大小）；区分"传输截断"与"内容损坏"。

### 修复「下载停止」的半成品无法删除

**已修复（1.2.7+）**。1.2.5 改用 `.part` 原子落盘后，「下载停止」的文件在磁盘上叫 `xxx.iso.part`，而前端传给删除接口的是目标名 `xxx.iso`。

- 修复：后端改为同时解析最终名与 `.part` 两条路径，删除实际存在的那些；前端「删除所选」的可删判定放宽为「完整文件 / 半成品 / 已下载 / 下载停止 / 下载失败 任一」。

## 性能优化

### 提高下载速度

1. **使用国内镜像源**：
   - 配置清华、中科大等国内镜像源
   - 在网络高峰期避免下载

2. **优化容器配置**：
   ```yaml
   # docker-compose.yml
   services:
     iso-hub:
       deploy:
         resources:
           limits:
             memory: 1G
             cpus: '0.5'
   ```

3. **网络调优**：
   - 确保主机网络带宽充足
   - 避免使用代理（除非必要）

### 减少磁盘占用

1. **定期清理**：
   - 使用"清理过期"功能
   - 定期手动删除不需要的文件

2. **存储优化**：
   - 将数据目录放在高速存储设备上
   - 使用压缩文件系统（如果支持）

## 故障排查工具

### 基本检查命令

```bash
# 检查容器状态
docker ps | grep iso-hub

# 检查服务健康
curl http://localhost:8899/api/health

# 查看日志
docker logs iso-hub --tail 100

# 检查磁盘空间
df -h /data

# 检查网络连接
curl -I https://mirrors.tuna.tsinghua.edu.cn/
```

### 日志分析

- **错误日志**：`docker logs iso-hub --tail 100 | grep ERROR`
- **下载日志**：`docker logs iso-hub --tail 50 | grep download`
- **同步日志**：`docker logs iso-hub --tail 50 | grep sync`
