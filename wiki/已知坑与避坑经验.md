# 已知坑与避坑经验

本页记录本项目开发和排错中踩过的坑与沉淀的方法论，供后续维护者参考。

## 后端 / 进程相关

### 子进程按行读 stdout，任何用 `\r` 无 `\n` 输出的库都会卡死

`subprocess.Popen` 后 `for raw in proc.stdout` 按行迭代，依赖换行符。**tqdm 进度条用 `\r`（回车）不换行**，会一直阻塞读，导致后端"卡住"。

- 现象：下载任务启动了，但日志/进度迟迟不输出。
- 解决：在 `web/iso_runner.py` 里**导入上游脚本前先 mock 掉 tqdm**：
  ```python
  import types, sys
  _tqdm_stub = types.ModuleType("tqdm")
  class _NoopTqdm:
      def __init__(self, *a, **k): pass
      def update(self, *a, **k): pass
      def __enter__(self): return self
      def __exit__(self, *a, **k): pass
      def close(self): pass
  _tqdm_stub.tqdm = lambda *a, **k: _NoopTqdm()
  sys.modules["tqdm"] = _tqdm_stub
  ```
- 通用原则：任何会 `\r` 刷新的库（tqdm / progressbar / rich live 等）在子进程里都可能阻塞按行读取，要么 mock、要么让输出走 stderr、要么后端改按字节块读。

### 命令参数含空格/逗号/引号时，别用 `.split(" ")` 拆 argv

- 旧 bug：`start_task` 把命令 join 成字符串，`_spawn_worker` 再 `.split(" ")`，把 JSON `--select` 拆坏，argparse 报 unrecognized arguments。
- 正确做法：命令存成 **list**，`subprocess.Popen(list)` 直接传，argparse 正常解析。

### 给子进程传参/收集状态，用专用带前缀的行协议

- 用 `#TARGET <path> <bytes>` 这类**哨兵行**从子进程回传结构化数据，后端拦截解析，不混入普通日志。
- 普通日志按行追加即可，但注意 tqdm 等 `\r` 输出（见上）。

## 前端 / 浏览器相关

### 单字母变量名遮蔽全局函数（最隐蔽的坑）

本项目全局有 i18n 翻译函数 `t()`。前端 JS 里若再用 `const t = xxx`（如 `const t = s.task`），就会**遮蔽全局 `t()`**，后续 `t('key')` 抛 `TypeError: t is not a function`。

- 若这段代码在 `try{...}catch(e){}` 里，错误被**静默吞掉**，UI 看似"没反应"（进度条不动、日志不刷），实则是抛了异常被吞。
- 教训：
  1. 翻译函数取名要更独特（如 `i18n` / `tr` / `__`），避免与业务变量冲突。
  2. 外层 try/catch 吞错误会掩盖根因，排查时要在 catch 里打印或先移除 catch 定位。
  3. 单字母变量名（`t`、`d`、`i`）极易撞车，业务里尽量用有语义的名。

### 浏览器缓存旧前端 → 各种"我改了没生效"

Flask 静态文件可能被浏览器缓存，改前端后用户看到的是旧 JS/HTML。

- 后端已对 `/api/` 加 `no-cache/no-store/must-revalidate`。
- 前端 `fetch` 已加 `cache:'no-store'`。
- 仍建议在 UI 放**版本徽章**（`APP_VERSION` / `VERSION_TAG`），用户一看数字就知道是不是最新，比反复猜测缓存强得多。
- 排查手段：**Ctrl+F5 强刷**，或看网络面板有没有 304。

### 定位前端运行时 bug，用真实浏览器逐条 eval

容器内 curl 测接口只能证明**后端**正常；前端运行时异常（变量遮蔽、DOM 找不到等）用真实浏览器最有效：

- 用 agent-browser 打开页面 → `snapshot -i` 拿元素 id → 点击下载 → `eval` 逐段跑 poll 内部逻辑 → 用 `console` 抓报错。
- 当年卡 0% 的根因（`t is not a function`）就是这么抓到的，比猜/看容器日志高效。

## 部署 / 网络相关

### 本机 git 对 GitHub push 会 Connection reset

- 现象：`git push` / `git fetch` 偶尔 `Recv failure: Connection was reset`。
- 解决：改用 **GitHub Contents API**（create blob → tree → commit → PATCH ref）推送，稳定可靠。
- 同步本地：`git fetch origin master` 失败时，用 API 确认远程 SHA 后 `git reset --hard origin/master`（但 fetch 失败的话 origin/master 可能旧，需以 API 返回为准）。

### 服务器原生 Samba 占用 445 → 容器 Samba 用高位端口

- 极空间 Z4Pro 自带 Samba 占用 445/139/137/138，容器版 Samba 映射到 **1445/1139/1137/1138**。
- 客户端访问要按实际映射端口填。

### 暴露公网，别忘了防火墙

- 腾讯云 Lighthouse/轻量：默认只放行 22/80，**其他端口（8899/1445/8081）需在控制台安全组放行**。
- 容器内验证：`curl http://127.0.0.1:8899/api/health`；公网验证：从别的机器 `nc -vz <IP> 8899`。
