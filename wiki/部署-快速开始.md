# 快速部署

ISO Hub 提供三种部署方式，任选其一：

| 方式 | 适合场景 | 容器构成 |
|---|---|---|
| **1.2 阿里云源** | **国内服务器（推荐）**：拉取快、公开仓库无需登录 | iso-hub 走阿里云 ACR，其余组件按 profile 按需拉 Docker Hub |
| 1.1 Docker Hub 源 | 海外服务器 | 全部走 Docker Hub |
| 2. 源码构建 | 需要改代码 / 自定义 iso-hub 镜像 | iso-hub 本地构建，其余组件同左侧 |

> **三种方式共用同一套 compose，容器构成完全一致**：直接 `docker compose up -d` **只起 iso-hub + socket-proxy 两个容器**。
> samba / webdav 挂在 `share` profile 下、qbittorrent 挂在 `bt` profile 下，**都是默认不部署**，需要哪个就单独加 `--profile` 启用 —— 详见「按需启用 sidecar 容器」。

## 前置要求

- 一台 Linux 服务器（或 NAS），已装 **Docker** + **Docker Compose**。
- 至少 2 核 / 2G 内存 / 足够放 ISO 的磁盘（一个发行版镜像通常 1–10GB）。
- 国内服务器建议配好 Docker 镜像加速（见下文）。

---

## 1. 使用 Docker 部署

直接拉取现成镜像，**无需本地构建**。以下两种镜像源内容相同，按网络情况任选其一。

### 1.1 Docker Hub 源部署方式

镜像由 GitHub Actions 在每次 push 到 `master` 时自动构建并推送。

**docker run 方式：**

```bash
docker pull dcchendockeruser/iso-hub:latest

mkdir -p data && sudo chown -R 10001:10001 data   # 容器以 uid 10001 非 root 运行

docker run -d --name iso-hub \
  -p 8899:8080 \
  -v "$PWD/data:/data" \
  --user 10001:10001 \
  --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --tmpfs /home/isohub:rw,nosuid,size=8m,uid=10001,gid=10001,mode=700 \
  -e TZ=Asia/Shanghai \
  -e ISO_HUB_ADMIN_USER='<设置用户名>' \
  -e ISO_HUB_ADMIN_PASS='<设置密码>' \
  dcchendockeruser/iso-hub:latest
```

> `--user` / `--read-only` / `--tmpfs` 是 v1.5.0 的加固项，漏了也能跑（镜像内已 `USER 10001`），但会退化成"非 root 可写根文件系统"。**`chown` 不能漏**：宿主目录属主不对时容器会启动即退出并打印迁移命令。

> 后两行 `-e` 是**管理员账号播种**（用户表为空时自动建号），把 `<设置用户名>` / `<设置密码>` 换成你自己的。**公网部署必设** —— 不设只能在服务器本机首次登录建号（见「首次启动必做」）。
> 值必须用引号包起来：`<` 在 shell 里是重定向符号，写成 `-e ISO_HUB_ADMIN_USER=<设置用户名>`（不加引号）会直接**语法报错、命令整条不执行**。
> ⚠️ 这条 `docker run` **不挂 `docker.sock`** → 面板里的「启停/重建 sidecar」不可用，且 SMB/WebDAV/qBittorrent 会显示「未部署」。这是**预期降级**（下载、校验、清单、外部 qB 种子都不受影响），详见下文「关于 Docker 权限」。要从面板管理三个 sidecar，请改用下面的 compose 方式。

**docker compose 方式**（默认两个容器：iso-hub + socket-proxy；SMB / WebDAV / 种子下载按需启用）：

保存为 `docker-compose.yml`：

```yaml
services:
  iso-hub:
    image: dcchendockeruser/iso-hub:latest    # Docker Hub 源
    container_name: iso-hub
    restart: unless-stopped
    # 等 socket-proxy 就绪再启动, 避免启动瞬间查到「未知」(代理未起)
    depends_on:
      socket-proxy:
        condition: service_healthy
    # 非 root + 只读根文件系统(v1.5.0)
    # ⚠️ 启动前先: mkdir -p data && sudo chown -R 10001:10001 data
    user: "10001:10001"
    read_only: true
    tmpfs:
      - /tmp:mode=1777,size=64m
      # gpg homedir 兜底: --show-keys 也会在这里建 pubring.kbx
      - /home/isohub:mode=700,uid=10001,gid=10001,size=8m
    # 安全: 丢弃全部 capabilities + 禁止提权(进程不需要任何特权操作)
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges:true
    ports:
      - "${ISO_HUB_PORT:-8899}:8080"
    volumes:
      - ./data:/data
      - ./samba-config:/samba-config     # samba 凭据文件, 与 samba 容器共享
      # 安全: 主容器不挂裸 /var/run/docker.sock(它等价宿主机 root), 改经 socket-proxy 白名单转发
    environment:
      - TZ=Asia/Shanghai
      # 经 socket-proxy 访问 Docker Engine API(白名单端点); 不需要容器管理时可整条删掉
      - DOCKER_HOST=tcp://socket-proxy:2375
      - ISO_HUB_TOKEN=${ISO_HUB_TOKEN:-}
      # (可选) 对 data/settings.json 整文件做 AES-GCM 静态加密(不设则明文, 向后兼容)。
      # 生产建议用 ISO_HUB_SECRET_KEY_FILE 从 Docker secret/只读文件读密钥, 例:
      #   ISO_HUB_SECRET_KEY=<随机字符串>  或   ISO_HUB_SECRET_KEY_FILE=/run/secrets/iso_hub_secret
      - ISO_HUB_SECRET_KEY=${ISO_HUB_SECRET_KEY:-}
      - ISO_HUB_SECRET_KEY_FILE=${ISO_HUB_SECRET_KEY_FILE:-}
      - ISO_HUB_REQUIRE_LOGIN=${ISO_HUB_REQUIRE_LOGIN:-1}
      # 管理员账号播种: 用户表为空时自动建号。**公网部署必设** —— 不设的话
      # 只能在服务器本机首次登录建号(防抢注), 公网打开登录页会提示「管理员账号未设置」。
      # 下面两行从 compose 同目录的 .env 读值(真值写在 .env, 见「首次启动必做」)。
      # 也可以直接在这里写死, 但 compose 通常要进 git, 密码写进去就等于公开:
      #   ISO_HUB_ADMIN_USER=<设置用户名>
      #   ISO_HUB_ADMIN_PASS=<设置密码>
      - ISO_HUB_ADMIN_USER=${ISO_HUB_ADMIN_USER:-}
      - ISO_HUB_ADMIN_PASS=${ISO_HUB_ADMIN_PASS:-}
      - ISO_HUB_SYNC_INTERVAL=${ISO_HUB_SYNC_INTERVAL:-86400}
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request as u;u.urlopen('http://127.0.0.1:8080/api/health',timeout=4)"]
      interval: 60s
      timeout: 5s
      retries: 3
      start_period: 15s

  samba:
    image: dperson/samba:latest
    container_name: iso-hub-samba
    restart: no                     # sidecar 默认不自愈: 宿主机重启后需手动再 up(见「按需启用 sidecar 容器」)
    profiles: ["share"]             # 挂在 share profile 下, 不加 --profile share 就不会部署
    ports:
      - "${SAMBA_PORT:-1445}:445"
      - "${SAMBA_NETBIOS:-1137}:137/udp"
      - "${SAMBA_138:-1138}:138/udp"
      - "${SAMBA_139:-1139}:139"
    # 凭据不进 command(明文会长期留在 docker inspect 的 .Config.Cmd), 改由启动脚本读文件
    entrypoint: ["/sbin/tini", "--", "/bin/sh", "/etc/iso-hub/samba-entrypoint.sh"]
    volumes:
      - ./data:/srv/iso:ro
      - ./samba-config:/samba-config:ro
      - ./docker/samba-entrypoint.sh:/etc/iso-hub/samba-entrypoint.sh:ro
    environment:
      - TZ=Asia/Shanghai
      - USERID=${SAMBA_UID:-0}
      - GROUPID=${SAMBA_GID:-0}
      - SAMBA_USERS_FILE=/samba-config/samba-users.conf

  webdav:
    image: hacdias/webdav:latest
    container_name: iso-hub-webdav
    restart: no                     # 同上
    profiles: ["share"]             # 挂在 share profile 下, 与 samba 一并按需启用
    ports:
      - "${WEBDAV_PORT:-8081}:6065"
    volumes:
      - ./data:/data:ro
      - ./data/webdav.yml:/config.yml:ro
    environment:
      - TZ=Asia/Shanghai
    command: ["-c", "/config.yml"]

  # ---------- Docker socket 代理: 收窄主容器对 Docker API 的访问权限 ----------
  # 只有本代理持有裸 /var/run/docker.sock(且只读挂载), 主容器经它按白名单调用。
  # 白名单写在 docker/socket-proxy/haproxy.cfg: 只放行 GET /containers/* 与
  # POST .../(start|stop|restart|update), 其余一律 403(含 create/delete/exec)。
  # 为什么不用上游 env 开关: POST=1 会把 /containers 前缀整体放行(连带 create/delete),
  # POST=0 又会把 start/stop 一起拒掉, 两个需求无法同时表达。
  # 说明: 不需要在面板里管理 sidecar 的话, 本服务连同主容器的 DOCKER_HOST / depends_on
  #       可以三处一起删掉(详见下文「关于 Docker 权限」)。
  socket-proxy:
    # 锁定 digest 而非 :latest —— 镜像行为变更会直接影响放行范围, 内容寻址可防漂移。
    image: haproxy:2.8-alpine@sha256:094401c230b9bf01a6a4dc96e455795e261483f3bd2f42f19d0e6f259bd43837
    container_name: iso-hub-socket-proxy
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - ./docker/socket-proxy/haproxy.cfg:/usr/local/etc/haproxy/haproxy.cfg:ro
      # 只有该代理持有裸 sock, 且以只读方式挂载
      - /var/run/docker.sock:/var/run/docker.sock:ro
    healthcheck:
      # 用代理镜像自带的 wget 探 /_ping(白名单放行), 代理未就绪则 unhealthy
      test: ["CMD-SHELL", "wget -q -O /dev/null http://localhost:2375/_ping || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 10s
    # 仅容器网络内部可达, 不对外暴露端口
```

启动：

```bash
mkdir -p /opt/iso-hub/data && cd /opt/iso-hub
docker compose pull
docker compose up -d
```

打开 `http://<服务器IP>:8899` 即可。

> 到这里**只有 iso-hub + socket-proxy 两个容器在跑**，网页主功能可用，但 SMB / WebDAV 尚未部署（面板里会显示「未部署」）。需要共享就先在「设置 → 共享设置」里填好密码并保存，再按「按需启用 sidecar 容器」执行 `sudo docker compose --profile share up -d samba`（WebDAV 同理），起来后访问 `smb://<IP>:1445/iso` / `http://<IP>:8081/dav`，账号 `iso` / 密码即你刚设置的那个（1.3.21 起没有默认口令，密码为空会拒绝启用）。

| 项目 | 值 |

| 镜像地址 | `registry.cn-hangzhou.aliyuncs.com/dcchen/isohub` |
| 可用标签 | `latest`（push master 时构建）；`1.0.6` 这类版本号（打 `v1.0.6` tag 时构建） |
| 构建方式 | GitHub Actions（workflow：`.github/workflows/aliyun-acr.yml`）自动构建推送 |

## 非 root 运行与目录属主（v1.5.0 起）

容器进程**不再是 root**，固定 `uid/gid = 10001`，根文件系统**只读**（只多挂一个 64MB 内存盘 `/tmp`）。

| 项 | v1.4.x 及以前 | v1.5.0 起 |
|---|---|---|
| 进程身份 | root | **10001:10001** |
| 根文件系统 | 可写 | **只读**（`/app`、site-packages 都写不了，重启即复原） |
| 可写位置 | 任意 | 仅 `./data` `./qb-config` `./webdav-config` `./samba-config`，外加两块内存盘 `/tmp`、`/home/isohub` |

### 为什么必须手动 chown

绑定挂载（`-v ./data:/data`）的**属主由宿主机决定**，容器内的 `chown` 只改镜像层，挂载一盖上去就失效了。而 Docker 在宿主目录不存在时会自动 `mkdir`，属主是 **root:root** —— 于是 uid 10001 的进程一个字节都写不了。这不是"能忍的小毛病"，是启动即失败。

所以无论是全新部署还是从 1.4.x 升级，**先 chown 再启动**：

```bash
docker compose down
sudo chown -R 10001:10001 ./data ./qb-config ./webdav-config ./samba-config
docker compose pull && docker compose up -d
```

### 漏了会怎样

启动自检会**立即中止**并在日志里打印上面那条命令：

```text
✖ 不可写: 数据目录 (/data) —— Permission denied

✖ 启动中止: 数据目录不可写。
  v1.5.0 起容器以非 root(uid/gid 10001)运行, 绑定挂载的属主由**宿主机**决定,
  容器内改不了。升级时请在 docker-compose.yml 所在目录执行:
      chown -R 10001:10001 ./data ./qb-config ./webdav-config ./samba-config
```

之所以选择"启动即失败"而不是"带病运行"：后者会表现为"面板能开、列表能看，但一点下载/删除就 500"，排查成本高得多。

### 怎么确认当前状态

`/api/health` 的 `writable` 字段逐项给出各挂载点是否可写：

```bash
curl -s http://127.0.0.1:8899/api/health | python3 -m json.tool
# "writable": {"data": true, "logs": true, "qb_config": true,
#              "webdav_config": true, "samba_config": true}
```

`missing`（未挂载）在 `writable` 里同样显示 `false` —— 它确实写不进去；但它只有出现在 `data` 上才是致命的。

### 特殊环境

| 环境 | 做法 |
|---|---|
| **NFS / SMB 挂载的 data** | 服务端映射 uid 10001，或 `all_squash,anonuid=10001,anongid=10001`；本机 `chown` 对远端无效 |
| **Podman / rootless Docker** | 没有真正的 uid 0，用 `userns_mode: keep-id`，或直接给宿主目录对应属主 |
| **群晖/极空间等 NAS** | 面板里给共享目录设"允许 10001 读写"，或 SSH 进去 `chown` |
| **必须回退** | compose 里给 `iso-hub` 加 `user: "0:0"` 并删掉 `read_only: true`（应急用，会失去本次全部收益） |

### 为什么 `read_only` 站得住

逐一核对过运行期的写盘点：

- `PYTHONDONTWRITEBYTECODE=1` → 不生成 `__pycache__`；
- gpg 的导入/导出/验签**全部**走 `tempfile.TemporaryDirectory()`（落在 `/tmp`）并显式传 `GNUPGHOME`，不碰 `$HOME/.gnupg`；
- `/home/isohub` 另挂 8MB 内存盘兜底：`gpg --show-keys` 看着只读文件，实际仍会在 homedir 建 `pubring.kbx`；不可写时它会 `Fatal` 且**一行指纹都不输出**，上层于是误判"缓存 keyring 指纹被篡改"，每轮下载都删掉重建，公钥源不可达时还会降级成只校验 SHA256。代码里已把这次调用也改成临时 homedir，tmpfs 是第二道保险；
- 业务写盘只有四类：`/data`（清单、设置、日志、下载）、`/qb-config`（改 WebUI 密码）、`/webdav-config`（生成 webdav.yml）、`/samba-config`（写账号文件），全是显式挂载的可写卷。

### qBittorrent 必须同 uid

`qbittorrent` 服务的 `QB_PUID` / `QB_PGID` 默认值已从 `0` 改为 `10001`。原因是它把 ISO 直接写进 `/data`：**以 root 写进去的文件，uid 10001 的主容器既校验不了也删不掉**（`cap_drop: ALL` 后没有 `DAC_OVERRIDE`）。老部署若在 `.env` 里显式钉过 `QB_PUID=0`，请一并改掉。

> samba sidecar 仍以 root 启动（`dperson/samba` 的入口脚本要 `usermod`/`chpasswd`，降权起不来），但它只是**只读**挂载 `./data` 并解析主容器写的 `0600` 账号文件，权限面很小。

## 关于 Docker 权限：socket-proxy 与「不挂 socket」的降级行为

### 为什么不是直接挂 `docker.sock`

`/var/run/docker.sock` 等价于宿主机 **root 权限**（拿到它就能创建特权容器、读写宿主机任意文件）。把它直接挂进 iso-hub 主容器，等于把整机交给一个对外提供 HTTP 服务的容器。

因此上面的 compose 示例里：**只有 `socket-proxy` 持有裸 sock（且 `:ro` 只读挂载）**，主容器改经 `DOCKER_HOST=tcp://socket-proxy:2375` 按白名单调用 Docker API —— 仅放行 `/containers/*` 与 start/stop，镜像 / 卷 / 网络 / exec / 系统五类端点一律禁掉。这与仓库自带的 `docker-compose.yml` / `docker-compose.acr.yml` / `docker-compose.dockerhub.yml` 完全一致。

### 不挂 socket 是受支持的「降级形态」，不是故障

| 能力 | 有 socket-proxy（或 `DOCKER_HOST`） | 不挂 socket |
|---|---|---|
| 下载 / 校验 / 清单 / 订阅同步 / 种子（外部 qB） | ✅ | ✅ |
| 面板查 SMB、WebDAV、qBittorrent 三个 sidecar 的状态 | ✅ | ❌ 显示「未部署」或「未知」 |
| 面板启停 / 重建 sidecar、补自愈重启策略 | ✅ | ❌ |
| 面板「日志」页 | 干净 | 启动收敛阶段仍会查容器 → 曾刷 `查询容器 ... FileNotFoundError`（**beta 2.4 起已降噪**：同一容器 + 同一异常 5 分钟内只打首条，并在首条附「挂 `docker.sock` 或设 `DOCKER_HOST`」的提示） |

所以**单容器部署**完全没问题：1.1 / 1.2 里的 `docker run` 一行命令就是这种形态；极空间 Z4Pro 这类 NAS 上只跑 iso-hub、SMB/WebDAV 用系统自带、种子交给外部 qBittorrent，也是这种形态。只要不指望**面板**去管容器，功能不受影响。

### 想要「零告警」的极简部署

确认不需要容器管理后，把这三处**一起**删掉即可（三者必须同进同退，否则 compose 起不来、或主容器空连一个不存在的代理）：

1. `socket-proxy:` 整个服务定义；
2. iso-hub 服务的 `DOCKER_HOST=tcp://socket-proxy:2375`；
3. iso-hub 服务的 `depends_on: socket-proxy`。

删掉后 sidecar 仍能正常跑（它们自己就是普通容器），只是**不能从面板里启停** —— 需要启停就直接 `docker compose --profile share up -d samba webdav` 或 `docker start iso-hub-samba`。

> 仓库自带的三份 compose（`docker-compose.yml` / `docker-compose.dockerhub.yml` / `docker-compose.acr.yml`）在这一点上完全一致：默认只有 **iso-hub + socket-proxy 两个容器**会起来；samba / webdav 挂在 `share` profile 下，qbittorrent 挂在 `bt` profile 下，**不指定 profile 就不会部署**。上面 1.1 / 1.2 的示例与仓库保持一致，同样带 `profiles: ["share"]`，照抄后行为和用仓库文件一模一样（示例不含 qbittorrent）。按需启用的完整命令见「按需启用 sidecar 容器」。

## 2. 使用源码构建部署（含 SMB/WebDAV 共享）

需要改代码、或想自定义 iso-hub 镜像时用这种方式。默认构建并启动 **iso-hub + socket-proxy 两个容器**，共享 / 种子那几个 sidecar 仍拉现成镜像、按 profile 按需启用。

```bash
git clone https://github.com/DC1024/iso-hub.git
cd iso-hub

# 可选：设置访问令牌（公网强烈建议）
# echo "ISO_HUB_TOKEN=你的随机密码" > .env

# 公网部署还要播种管理员账号（不设则只能在服务器本机首次登录建号）：
# echo "ISO_HUB_ADMIN_USER=你的用户名" >> .env
# echo "ISO_HUB_ADMIN_PASS=你的强密码" >> .env
# chmod 600 .env

# 容器以 uid 10001 非 root 运行, 先把挂载目录交给它(v1.5.0 起)
mkdir -p data qb-config webdav-config samba-config
sudo chown -R 10001:10001 data qb-config webdav-config samba-config

docker compose up -d --build
```

打开 `http://<服务器IP>:8899` 即可。需要 SMB / WebDAV / 种子下载时，按「按需启用 sidecar 容器」加 `--profile share` / `--profile bt` 启起来（源码克隆目录就是 compose 所在目录，直接在仓库根目录执行）。

## 国内服务器镜像加速

源码构建时 `pip install` 依赖可指定国内 PyPI 源加速（在 `docker-compose.yml` 同级 `.env` 写）：

```ini
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
```

拉镜像若有困难，可在 Docker daemon 配置 registry-mirrors（如 docker.1panel.live / docker.m.daocloud.io 等，视可用性而定）。

## 首次启动必做

1. **创建管理员账号**（单管理员账号，PBKDF2-SHA256 加密存储）。两种方式二选一：

   **方式 A（推荐，公网部署必做）：环境变量播种**

   在 compose 文件**同目录**建 `.env`（真值写这里，不要写进 yml）：

   ```bash
   cd /opt/iso-hub
   cat > .env <<'EOF'
   ISO_HUB_ADMIN_USER=admin
   ISO_HUB_ADMIN_PASS=改成你的强密码
   EOF
   chmod 600 .env          # 只会本机可读，避免密码泄露给其他用户
   docker compose up -d
   ```

   - 容器启动时若用户表为空，会自动用这两个变量建号；**同名账号已存在则不覆盖**。
   - 为什么真值放 `.env` 而不是 yml：compose 文件通常要进 git，密码写进去就等于公开；`.env` 可加进 `.gitignore`，且 `chmod 600` 后只有 root 能读。
   - 账号建好后改 `.env` 重启**不会**改密码，改密走面板「设置 → 修改密码」。

   **方式 B（不设环境变量）：从服务器本机首次登录建号**

   不设 `ISO_HUB_ADMIN_USER` / `ISO_HUB_ADMIN_PASS` 时，第一个登录的人就是管理员，但**只允许从服务器本机发起**（防抢注）。用 SSH 隧道把服务器端口映射到本地：

   ```bash
   ssh -L 8899:127.0.0.1:8899 '<user>@<服务器IP>'
   ```

   （引号不能省：shell 会把 `<` 当重定向，不加引号这条命令直接语法报错。）

   保持该窗口开着，本机浏览器访问 <http://localhost:8899>，在登录页输入想用的账号密码即完成建号。建好后公网访问同一账号密码可直接登录。

   > ⚠️ **公网 IP 直接打开登录页会报「管理员账号未设置」，这是预期行为，不是故障**：`/api/user/login` 有防抢注逻辑，用户表为空时只放行 `127.0.0.1` / `::1`，公网请求一律 403。想从公网建号请用方式 A。

2. **抓取最新元数据**：点右上角「抓取最新版本元数据」，把内置样例清单刷新为当前镜像站上的最新版本。
3. **下载**：勾选发行版/版本，点「下载」。

> **（可选）给 settings.json 加静态加密**：默认 settings.json 明文落盘。若想让磁盘上的共享凭据等敏感数据变成密文，给 iso-hub 容器设置 `ISO_HUB_SECRET_KEY`（或 `ISO_HUB_SECRET_KEY_FILE`）即可，对网页用户透明。详见「环境变量与路径」的 *settings.json 静态加密* 一节。

## 按需启用 sidecar 容器（SMB / WebDAV / qBittorrent）

网络共享和种子下载不是人人都要，所以它们被塞进独立的 **compose profile**，默认不部署。三个 sidecar 的归属：

| 服务名 | 所属 profile | 作用 | 访问方式 |
|---|---|---|---|
| `samba` | `share` | SMB 共享 `./data` | `smb://<服务器IP>:1445/iso` |
| `webdav` | `share` | WebDAV 共享 `./data` | `http://<服务器IP>:8081/dav` |
| `qbittorrent` | `bt` | 种子 / 磁力下载 | WebUI `http://<服务器IP>:8090` |

### 第一步：先 cd 进 compose 文件所在目录

**这一步不能省。** compose 里的挂载写的是相对路径（`./data`、`./qb-config`、`./webdav-config`），Compose 以**当前 shell 所在目录**为基准解释它们：

- 在别的目录执行 → 数据卷会建到意想不到的位置（`./data` 变成那个目录下的 `data/`），主容器数据看起来「凭空消失」；
- 目录里没有 compose 文件 → 直接报 `no configuration file provided`，一行都不执行。

仓库示例默认放在 `/opt/iso-hub`，先进去（换成你实际存放 compose 的目录）：

```bash
cd /opt/iso-hub
```

### 第二步：按需要启用

```bash
# SMB 共享（端口 1445）
sudo docker compose -f docker-compose.acr.yml --profile share up -d samba

# WebDAV（端口 8081）
sudo docker compose -f docker-compose.acr.yml --profile share up -d webdav

# 种子下载 qBittorrent（WebUI 端口 8090）
sudo docker compose -f docker-compose.acr.yml --profile bt   up -d qbittorrent
```

> `-f docker-compose.acr.yml` 只在**文件名不是默认的 `docker-compose.yml`** 时才需要写。用 1.1 / 源码构建那份 `docker-compose.yml` 时把 `-f ...` 省掉即可：`sudo docker compose --profile share up -d samba`。
> 加 `--profile` 只会额外拉起对应 sidecar，**不会停用已跑着的默认两个容器**。

一次性把两个共享都起来，或者连主服务一起重建：

```bash
# 起默认两容器 + samba + webdav
sudo docker compose -f docker-compose.acr.yml --profile share up -d
# 再把种子下载也加上
sudo docker compose -f docker-compose.acr.yml --profile share --profile bt up -d
```

### 停止 / 查看 / 排错

```bash
sudo docker compose -f docker-compose.acr.yml --profile share ps            # 查看（不加 profile 看不到 sidecar）
sudo docker compose -f docker-compose.acr.yml --profile share logs -f samba # 看日志
sudo docker compose -f docker-compose.acr.yml --profile share stop samba webdav
```

⚠️ 两个容易踩的点：

1. **宿主机重启后 sidecar 不会自动回来** —— 三个 sidecar 的 `restart` 策略是 `no`（与仓库 compose 一致），重启机器后要重跑一次上面的 up 命令。想让它跟着 Docker 自动起，就把 compose 里对应服务的 `restart: no` 改成 `unless-stopped`（代价是「开没开」不再完全由你决定）。
2. **端口被占会起不来** —— SMB 用 1445（宿主机的 445 通常被系统自带 Samba 占着）、WebDAV 用 8081、qBittorrent 用 8090。改端口在 compose 同目录的 `.env` 里写：`SAMBA_PORT=` / `WEBDAV_PORT=` / `QB_PORT=`。

## 常见部署失败

| 现象 | 处理 |
|---|---|
| 构建时 pip 超时 | 配 `PIP_INDEX_URL` 为国内源 |
| 8899 访问不了 | 检查云厂商安全组/防火墙是否放行该端口 |
| 页面能开但下载就报错 | 看「常见问题」的下载报错条目 |
| 面板显示 SMB / WebDAV / qBittorrent「未部署」 | 正常——sidecar 默认不部署。按「按需启用 sidecar 容器」跑 `docker compose --profile share up -d samba`（qBittorrent 用 `--profile bt`） |
| 执行 compose 报 `no configuration file provided` | 没 `cd` 进 compose 文件所在目录（本文的案例目录是 `/opt/iso-hub`） |
| 容器起来几秒就退出，日志写「启动中止: 数据目录不可写」 | v1.5.0 的目录属主没迁移，执行 `sudo chown -R 10001:10001 ./data ./qb-config ./webdav-config ./samba-config` 后 `up -d`。详见「非 root 运行与目录属主」 |
| 面板能开，但下载/删除报 `Permission denied` | 同上；另外检查 `.env` 里是否把 `QB_PUID` / `QB_PGID` 钉成了 `0`，应为 `10001` |
| 日志出现 `gpg: failed to create temporary file` | `/tmp` 不可写 —— 检查 compose 里 `tmpfs: - /tmp` 是否还在（`read_only: true` 必须配它） |
