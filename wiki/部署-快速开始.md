# 快速部署

ISO Hub 提供三种部署方式，任选其一：

| 方式 | 适合场景 | 容器构成 |
|---|---|---|
| **1.2 阿里云源** | **国内服务器（推荐）**：拉取快、公开仓库无需登录 | iso-hub 走阿里云，socket-proxy / samba / webdav 走 Docker Hub |
| 1.1 Docker Hub 源 | 海外服务器 | 四容器均从 Docker Hub 拉取（iso-hub + socket-proxy + samba + webdav） |
| 2. 源码构建 | 需要改代码 / 自定义网络共享镜像 | 四容器本地构建（iso-hub + socket-proxy + samba + webdav） |

## 前置要求

- 一台 Linux 服务器（或 NAS），已装 **Docker** + **Docker Compose**。
- 至少 2 核 / 2G 内存 / 足够放 ISO 的磁盘（一个发行版镜像通常 1–10GB）。
- 国内服务器建议配好 Docker 镜像加速（见下文）。

---

## 1. 使用 Docker 部署

直接拉取现成镜像，**无需本地构建**。以下两种镜像源内容相同，按网络情况任选其一。

### 1.1 Docker Hub 源部署方式

镜像由 GitHub Actions 在每次 push 到 `master` 时自动构建并推送。

**docker run 方式：**

```bash
docker pull dcchendockeruser/iso-hub:latest

docker run -d --name iso-hub \
  -p 8899:8080 \
  -v "$PWD/data:/data" \
  -e TZ=Asia/Shanghai \
  -e ISO_HUB_ADMIN_USER='<设置用户名>' \
  -e ISO_HUB_ADMIN_PASS='<设置密码>' \
  dcchendockeruser/iso-hub:latest
```

> 后两行 `-e` 是**管理员账号播种**（用户表为空时自动建号），把 `<设置用户名>` / `<设置密码>` 换成你自己的。**公网部署必设** —— 不设只能在服务器本机首次登录建号（见「首次启动必做」）。
> 值必须用引号包起来：`<` 在 shell 里是重定向符号，写成 `-e ISO_HUB_ADMIN_USER=<设置用户名>`（不加引号）会直接**语法报错、命令整条不执行**。
> ⚠️ 这条 `docker run` **不挂 `docker.sock`** → 面板里的「启停/重建 sidecar」不可用，且 SMB/WebDAV/qBittorrent 会显示「未部署」。这是**预期降级**（下载、校验、清单、外部 qB 种子都不受影响），详见下文「关于 Docker 权限」。要从面板管理三个 sidecar，请改用下面的 compose 方式。

**docker compose 方式**（含 socket-proxy + SMB/WebDAV 共享，四个容器）：

保存为 `docker-compose.yml`：

```yaml
services:
  iso-hub:
    image: dcchendockeruser/iso-hub:latest    # Docker Hub 源
    container_name: iso-hub
    restart: unless-stopped
    # 等 socket-proxy 就绪再启动, 避免启动瞬间查到「未知」(代理未起)
    depends_on:
      socket-proxy:
        condition: service_healthy
    ports:
      - "${ISO_HUB_PORT:-8899}:8080"
    volumes:
      - ./data:/data
      # 安全: 主容器不挂裸 /var/run/docker.sock(它等价宿主机 root), 改经 socket-proxy 白名单转发
    environment:
      - TZ=Asia/Shanghai
      # 经 socket-proxy 访问 Docker Engine API(白名单端点); 不需要容器管理时可整条删掉
      - DOCKER_HOST=tcp://socket-proxy:2375
      - ISO_HUB_TOKEN=${ISO_HUB_TOKEN:-}
      # (可选) 对 data/settings.json 整文件做 AES-GCM 静态加密(不设则明文, 向后兼容)。
      # 生产建议用 ISO_HUB_SECRET_KEY_FILE 从 Docker secret/只读文件读密钥, 例:
      #   ISO_HUB_SECRET_KEY=<随机字符串>  或   ISO_HUB_SECRET_KEY_FILE=/run/secrets/iso_hub_secret
      - ISO_HUB_SECRET_KEY=${ISO_HUB_SECRET_KEY:-}
      - ISO_HUB_SECRET_KEY_FILE=${ISO_HUB_SECRET_KEY_FILE:-}
      - ISO_HUB_REQUIRE_LOGIN=${ISO_HUB_REQUIRE_LOGIN:-1}
      # 管理员账号播种: 用户表为空时自动建号。**公网部署必设** —— 不设的话
      # 只能在服务器本机首次登录建号(防抢注), 公网打开登录页会提示「管理员账号未设置」。
      # 下面两行从 compose 同目录的 .env 读值(真值写在 .env, 见「首次启动必做」)。
      # 也可以直接在这里写死, 但 compose 通常要进 git, 密码写进去就等于公开:
      #   ISO_HUB_ADMIN_USER=<设置用户名>
      #   ISO_HUB_ADMIN_PASS=<设置密码>
      - ISO_HUB_ADMIN_USER=${ISO_HUB_ADMIN_USER:-}
      - ISO_HUB_ADMIN_PASS=${ISO_HUB_ADMIN_PASS:-}
      - ISO_HUB_SYNC_INTERVAL=${ISO_HUB_SYNC_INTERVAL:-86400}
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request as u;u.urlopen('http://127.0.0.1:8080/api/health',timeout=4)"]
      interval: 60s
      timeout: 5s
      retries: 3
      start_period: 15s

  samba:
    image: dperson/samba:latest
    container_name: iso-hub-samba
    restart: unless-stopped
    ports:
      - "${SAMBA_PORT:-1445}:445"
      - "${SAMBA_NETBIOS:-1137}:137/udp"
      - "${SAMBA_138:-1138}:138/udp"
      - "${SAMBA_139:-1139}:139"
    volumes:
      - ./data:/srv/iso:ro
    environment:
      - TZ=Asia/Shanghai
      - USERID=${SAMBA_UID:-0}
      - GROUPID=${SAMBA_GID:-0}
    command: >-
      -p
      -u "${SAMBA_USER:-iso};${SAMBA_PASS:-iso123}"
      -s "iso;/srv/iso;no;no;no;${SAMBA_USER:-iso},${SAMBA_PASS:-iso123}"

  webdav:
    image: hacdias/webdav:latest
    container_name: iso-hub-webdav
    restart: unless-stopped
    ports:
      - "${WEBDAV_PORT:-8081}:6065"
    volumes:
      - ./data:/data:ro
      - ./data/webdav.yml:/config.yml:ro
    environment:
      - TZ=Asia/Shanghai
    command: ["-c", "/config.yml"]

  # ---------- Docker socket 代理: 收窄主容器对 Docker API 的访问权限 ----------
  # 只有本代理持有裸 /var/run/docker.sock(且只读挂载), 主容器经它按白名单调用。
  # 白名单: 仅放行 /containers/*(CONTAINERS=1) 与写操作(POST=1, start/stop 需要);
  #         禁掉镜像、卷、网络、exec、系统五类端点。
  # 说明: 不需要在面板里管理 sidecar 的话, 本服务连同主容器的 DOCKER_HOST / depends_on
  #       可以三处一起删掉(详见下文「关于 Docker 权限」)。
  socket-proxy:
    # 锁定 digest 而非 :latest —— 上游 ACL 行为变更会直接改变放行范围, 内容寻址可防漂移。
    image: tecnativa/docker-socket-proxy@sha256:1f5038b54f06c3e18422902cf00ba21803d1c97805aae032e5e6673d532d3459
    container_name: iso-hub-socket-proxy
    restart: unless-stopped
    environment:
      - CONTAINERS=1     # 允许 /containers/* 端点(查状态/启停/更新/重建)
      - POST=1           # 允许写操作(start/stop 是 POST; 该粒度较粗, 会连带放行 /containers/create)
      - IMAGES=0         # 禁止镜像操作
      - VOLUMES=0        # 禁止卷操作
      - NETWORKS=0       # 禁止网络操作
      - EXEC=0           # 禁止 exec
      - SYSTEM=0         # 禁止系统级操作
      - TZ=Asia/Shanghai
    volumes:
      # 只有该代理持有裸 sock, 且以只读方式挂载
      - /var/run/docker.sock:/var/run/docker.sock:ro
    healthcheck:
      # 用代理镜像自带的 wget 探 /_ping(白名单放行), 代理未就绪则 unhealthy
      test: ["CMD-SHELL", "wget -q -O /dev/null http://localhost:2375/_ping || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 10s
    # 仅容器网络内部可达, 不对外暴露端口
```

启动：

```bash
mkdir -p /opt/iso-hub/data && cd /opt/iso-hub
docker compose pull
docker compose up -d
```

打开 `http://<服务器IP>:8899` 即可。SMB `smb://<IP>:1445/iso`，WebDAV `http://<IP>:8081/dav`（账号 `iso` / 密码 `iso123`）。

### 1.2 阿里云 ACR 源部署方式（国内推荐）

国内服务器从 Docker Hub 拉取经常超时或失败，因此镜像同时推送到 **阿里云容器镜像服务（华东1·杭州）**。该仓库已设为**公开**，**无需 `docker login`** 即可直接拉取，国内速度明显更快。

| 项目 | 值 |
|---|---|
| 镜像地址 | `registry.cn-hangzhou.aliyuncs.com/dcchen/isohub` |
| 可用标签 | `latest`（push master 时构建）；`1.0.6` 这类版本号（打 `v1.0.6` tag 时构建） |
| 构建方式 | GitHub Actions（workflow：`.github/workflows/aliyun-acr.yml`）自动构建推送 |

**docker compose 方式（推荐，含 socket-proxy + SMB/WebDAV 共享，四个容器）：**

## 关于 Docker 权限：socket-proxy 与「不挂 socket」的降级行为

### 为什么不是直接挂 `docker.sock`

`/var/run/docker.sock` 等价于宿主机 **root 权限**（拿到它就能创建特权容器、读写宿主机任意文件）。把它直接挂进 iso-hub 主容器，等于把整机交给一个对外提供 HTTP 服务的容器。

因此上面的 compose 示例里：**只有 `socket-proxy` 持有裸 sock（且 `:ro` 只读挂载）**，主容器改经 `DOCKER_HOST=tcp://socket-proxy:2375` 按白名单调用 Docker API —— 仅放行 `/containers/*` 与 start/stop，镜像 / 卷 / 网络 / exec / 系统五类端点一律禁掉。这与仓库自带的 `docker-compose.yml` / `docker-compose.acr.yml` / `docker-compose.dockerhub.yml` 完全一致。

### 不挂 socket 是受支持的「降级形态」，不是故障

| 能力 | 有 socket-proxy（或 `DOCKER_HOST`） | 不挂 socket |
|---|---|---|
| 下载 / 校验 / 清单 / 订阅同步 / 种子（外部 qB） | ✅ | ✅ |
| 面板查 SMB、WebDAV、qBittorrent 三个 sidecar 的状态 | ✅ | ❌ 显示「未部署」或「未知」 |
| 面板启停 / 重建 sidecar、补自愈重启策略 | ✅ | ❌ |
| 面板「日志」页 | 干净 | 启动收敛阶段仍会查容器 → 曾刷 `查询容器 ... FileNotFoundError`（**beta 2.4 起已降噪**：同一容器 + 同一异常 5 分钟内只打首条，并在首条附「挂 `docker.sock` 或设 `DOCKER_HOST`」的提示） |

所以**单容器部署**完全没问题：1.1 / 1.2 里的 `docker run` 一行命令就是这种形态；极空间 Z4Pro 这类 NAS 上只跑 iso-hub、SMB/WebDAV 用系统自带、种子交给外部 qBittorrent，也是这种形态。只要不指望**面板**去管容器，功能不受影响。

### 想要「零告警」的极简部署

确认不需要容器管理后，把这三处**一起**删掉即可（三者必须同进同退，否则 compose 起不来、或主容器空连一个不存在的代理）：

1. `socket-proxy:` 整个服务定义；
2. iso-hub 服务的 `DOCKER_HOST=tcp://socket-proxy:2375`；
3. iso-hub 服务的 `depends_on: socket-proxy`。

删掉后 sidecar 仍能正常跑（它们自己就是普通容器），只是**不能从面板里启停** —— 需要启停就直接 `docker compose up -d samba webdav` 或 `docker start iso-hub-samba`。

> 仓库自带的 compose 把 samba / webdav / qbittorrent 放在 `share` / `bt` 两个 compose profile 下（默认不部署，需要时 `docker compose --profile share up -d`）。上面 1.1 / 1.2 的示例为便于上手**不设 profile**，samba / webdav 两个 sidecar 随主服务一起起（示例不涉及 qbittorrent）。

## 2. 使用源码构建部署（含 SMB/WebDAV 共享）

需要网络共享（SMB/WebDAV）或想改代码时用这种方式，会构建 iso-hub 主服务 + socket-proxy + samba + webdav **四个容器**。

```bash
git clone https://github.com/DC1024/iso-hub.git
cd iso-hub

# 可选：设置访问令牌（公网强烈建议）
# echo "ISO_HUB_TOKEN=你的随机密码" > .env

# 公网部署还要播种管理员账号（不设则只能在服务器本机首次登录建号）：
# echo "ISO_HUB_ADMIN_USER=你的用户名" >> .env
# echo "ISO_HUB_ADMIN_PASS=你的强密码" >> .env
# chmod 600 .env

docker compose up -d --build
```

打开 `http://<服务器IP>:8899` 即可。

## 国内服务器镜像加速

源码构建时 `pip install` 依赖可指定国内 PyPI 源加速（在 `docker-compose.yml` 同级 `.env` 写）：

```ini
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
```

拉镜像若有困难，可在 Docker daemon 配置 registry-mirrors（如 docker.1panel.live / docker.m.daocloud.io 等，视可用性而定）。

## 首次启动必做

1. **创建管理员账号**（单管理员账号，PBKDF2-SHA256 加密存储）。两种方式二选一：

   **方式 A（推荐，公网部署必做）：环境变量播种**

   在 compose 文件**同目录**建 `.env`（真值写这里，不要写进 yml）：

   ```bash
   cd /opt/iso-hub
   cat > .env <<'EOF'
   ISO_HUB_ADMIN_USER=admin
   ISO_HUB_ADMIN_PASS=改成你的强密码
   EOF
   chmod 600 .env          # 只会本机可读，避免密码泄露给其他用户
   docker compose up -d
   ```

   - 容器启动时若用户表为空，会自动用这两个变量建号；**同名账号已存在则不覆盖**。
   - 为什么真值放 `.env` 而不是 yml：compose 文件通常要进 git，密码写进去就等于公开；`.env` 可加进 `.gitignore`，且 `chmod 600` 后只有 root 能读。
   - 账号建好后改 `.env` 重启**不会**改密码，改密走面板「设置 → 修改密码」。

   **方式 B（不设环境变量）：从服务器本机首次登录建号**

   不设 `ISO_HUB_ADMIN_USER` / `ISO_HUB_ADMIN_PASS` 时，第一个登录的人就是管理员，但**只允许从服务器本机发起**（防抢注）。用 SSH 隧道把服务器端口映射到本地：

   ```bash
   ssh -L 8899:127.0.0.1:8899 '<user>@<服务器IP>'
   ```

   （引号不能省：shell 会把 `<` 当重定向，不加引号这条命令直接语法报错。）

   保持该窗口开着，本机浏览器访问 <http://localhost:8899>，在登录页输入想用的账号密码即完成建号。建好后公网访问同一账号密码可直接登录。

   > ⚠️ **公网 IP 直接打开登录页会报「管理员账号未设置」，这是预期行为，不是故障**：`/api/user/login` 有防抢注逻辑，用户表为空时只放行 `127.0.0.1` / `::1`，公网请求一律 403。想从公网建号请用方式 A。

2. **抓取最新元数据**：点右上角「抓取最新版本元数据」，把内置样例清单刷新为当前镜像站上的最新版本。
3. **下载**：勾选发行版/版本，点「下载」。

> **（可选）给 settings.json 加静态加密**：默认 settings.json 明文落盘。若想让磁盘上的共享凭据等敏感数据变成密文，给 iso-hub 容器设置 `ISO_HUB_SECRET_KEY`（或 `ISO_HUB_SECRET_KEY_FILE`）即可，对网页用户透明。详见「环境变量与路径」的 *settings.json 静态加密* 一节。

## 常见部署失败

| 现象 | 处理 |
|---|---|
| 构建时 pip 超时 | 配 `PIP_INDEX_URL` 为国内源 |
| 8899 访问不了 | 检查云厂商安全组/防火墙是否放行该端口 |
| 页面能开但下载就报错 | 看「常见问题」的下载报错条目 |
