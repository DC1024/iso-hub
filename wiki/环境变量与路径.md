# 环境变量与路径速查

## 目录结构

```text
iso-hub/
├── docker-compose.yml     # 三容器编排（主服务 + samba + webdav）Docker Hub 源
├── docker-compose.acr.yml # 阿里云 ACR 源版三容器编排（iso-hub 走阿里云，samba/webdav 走 Docker Hub）
├── Dockerfile
├── .env.example           # 环境变量示例（复制为 .env 即可用）
├── .github/workflows/     # GitHub Actions 自动构建镜像
├── web/                   # Flask API + 前端 index.html + iso_runner.py
└── iso_download/          # 上游脚本（只读，勿改）
```

运行后产生的数据目录：

```text
data/
├── distributions.json     # 发行版清单（手动/自动刷新生成，持久化）
├── custom_sources.json    # 自定义源（独立保存，不被刷新覆盖）
├── custom_repo_cache.json # 自定义"发行版源"展开结果的持久化缓存（仅后台刷新写入）
├── subscriptions.json     # 订阅配置（发行版/保留版本数/开关/上次运行）
├── settings.json          # 网络共享凭据 + 自定义源自动刷新开关/间隔（网页改后写入，覆盖 .env 默认值）
├── webdav.yml             # WebDAV 凭据配置
└── linux/                 # 下载目录：{type}/{发行版}/{文件}
    ├── Ubuntu/ubuntu-26.04-live-server-amd64.iso
    └── Proxmox/proxmox-ve_9.1-1.iso
```

## 全部环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `ISO_HUB_PORT` | `8899` | 宿主机访问端口（映射到容器 8080） |
| `ISO_HUB_TOKEN` | 空 | 设置后所有写操作需弹窗输入令牌（公网建议开） |
| `ISO_HUB_REQUIRE_LOGIN` | `1` | 强制登录门禁：1=必须登录管理员（默认），0=关闭门禁直接可用 |
| `ISO_HUB_ADMIN_USER` | 空 | 管理员账号播种：用户表为空时自动创建该账号（需同时设 PASS） |
| `ISO_HUB_ADMIN_PASS` | 空 | 播种账号的初始密码；同名账号已存在时不覆盖 |
| `ISO_HUB_SYNC_INTERVAL` | `86400` | 订阅自动同步间隔(秒)；0=关闭内置调度器 |
| `SAMBA_USER` | `iso` | SMB 共享账号 |
| `SAMBA_PASS` | `iso123` | SMB 共享密码 |
| `SAMBA_PORT` | `1445` | SMB 445 端口在宿主机的映射（Z4Pro 原生 Samba 占 445 故用高位） |
| `SAMBA_NETBIOS` | `1137` | NetBIOS 137/udp 宿主端口 |
| `SAMBA_138` | `1138` | NetBIOS 138/udp 宿主端口 |
| `SAMBA_139` | `1139` | NetBIOS 139/tcp 宿主端口 |
| `SAMBA_UID` / `SAMBA_GID` | `0` | Samba 容器内进程 UID/GID（默认 root） |
| `WEBDAV_USER` | `iso` | WebDAV 账号 |
| `WEBDAV_PASS` | `iso123` | WebDAV 密码 |
| `WEBDAV_PORT` | `8081` | WebDAV 宿主端口 |
| `TZ` | `Asia/Shanghai` | 时区 |
| `ISO_HUB_SECRET_KEY` | 空（不设=明文） | **可选**。设置后对 `data/settings.json` 整文件做 AES-GCM 加密再落盘（静态加密 at-rest）；密钥字符串经 SHA-256 派生为 32 字节 AES-256 密钥。与登录密码无关。不设则保持明文（向后兼容，现有部署零变化）。 |
| `ISO_HUB_SECRET_KEY_FILE` | 空 | 密钥文件路径形式：从该文件读取密钥字节（strip 后）作为 `ISO_HUB_SECRET_KEY` 的替代。生产推荐（配合 Docker secret / 挂载文件），避免密钥明文出现在环境变量或 compose 里。两者都设时以 `ISO_HUB_SECRET_KEY` 优先。 |

## 环境变量优先级

`settings.json`（网页「设置 → 共享设置」改的）**优先于** `.env` 里的 `SAMBA_*` / `WEBDAV_*`。即：

1. 网页改密 → 写入 `./data/settings.json`（主容器会据此重写 `webdav.yml`）
2. 运行中的共享容器需 `docker compose restart samba webdav` 才生效

**管理员账号播种（`ISO_HUB_ADMIN_USER` / `ISO_HUB_ADMIN_PASS`）只在「还没号」时生效**：

| 时机 | 行为 |
|---|---|
| 启动容器时 | 用户表为空 → 用这两个变量自动建号；同名用户已存在 → 直接跳过，不覆盖 |
| 账号已建好后 | 改 `.env` 重启**不会**改密码（同名账号被跳过），也不会新建第二个号 |

所以**改密码必须走面板**：「设置 → 修改密码」（`POST /api/user/password`）。忘了密码只能清掉 `data/settings.json` 里的用户表再重启播种（会丢掉旧账号，谨慎）。

## settings.json 静态加密（at-rest encryption，可选）

`data/settings.json` 保存着网络共享凭据（SMB / WebDAV / qBittorrent 密码）、自定义源刷新开关、以及其他设置等敏感数据。默认以**明文**落盘（与旧版一致）。设置 `ISO_HUB_SECRET_KEY`（或 `ISO_HUB_SECRET_KEY_FILE`）后，主容器在**写入** settings.json 时先用 AES-GCM 整文件加密再落盘，磁盘上不再是明文；读取时自动解密。加解密都在主容器内完成，**对网页终端用户完全透明——普通用户无需、也不会接触这个密钥**。

要点：
- **密钥 ≠ 登录密码**：登录用的是 PBKDF2 哈希（`users.admin.password_hash`）；`ISO_HUB_SECRET_KEY` 只用于"磁盘加解密"，与认证无关。改登录密码不影响加密密钥，反之亦然。
- **平滑启用，无需迁移**：开启后不会立刻改写已有文件。只有当你在面板「设置」里改动任意一项（触发一次写入），文件才变成密文；此前旧明文文件仍可正常读取（明文回退）。所以不用手动转换。
- **密钥必须长期在场**：一旦文件已变密文，**运行时 `ISO_HUB_SECRET_KEY` 必须始终可用**，否则主容器读不出 settings（报"文件损坏/解密失败"）。密钥丢失 = settings.json 无法恢复，只能从备份还原。
- **密钥轮换不支持热切换**：目前没有双密钥机制。换密钥正确做法：先用旧密钥把 settings 备份，再改密钥并重建容器（首次写入会用新密钥重新加密）。切勿"直接改密钥"——旧密文用新密钥解不开，且应用可能把该文件当损坏重置成空配置（不可逆）。
- **权限收紧（档位 A）**：写入后文件 `chmod 600`。但容器以 root 运行，只能挡非 root 读者；主要保护仍是 AES-GCM + 密钥不进 data 卷。
- **作用范围**：仅 `settings.json` 被加密。WebDAV 凭据（`webdav.yml`，在 data 卷外）与 qBittorrent 密码（PBKDF2 哈希，非明文）不在其内；但 SMB/WebDAV/qB 在面板填的密码落在 settings.json 内，会被一并加密。启用加密后，面板「设置 → 共享设置」下方的黄色提示会变为"…若已设置外部密钥 ISO_HUB_SECRET_KEY，将以 AES-GCM 密文存储于磁盘"。

### 推荐部署方式

**方式一（最简单）：写进 `.env`** —— 密钥以明文存在于宿主机 `.env` 与容器环境变量。在 `docker-compose.acr.yml`（或 `.yml`）的 `iso-hub.environment` 增加一行（与现有 `ISO_HUB_*` 同风格）：

```yaml
      - ISO_HUB_SECRET_KEY=${ISO_HUB_SECRET_KEY:-}
```

并在 compose 同目录的 `.env` 写入：

```bash
# 生成一段强随机密钥
ISO_HUB_SECRET_KEY=$(openssl rand -hex 32)
```

**方式二（生产推荐）：用密钥文件 / Docker secret** —— 密钥字符串不进环境变量、不进 compose：

```bash
# 宿主机生成密钥文件并收紧权限
openssl rand -hex 32 | sudo tee /opt/iso-hub/secret/iso_hub_key >/dev/null
sudo chmod 600 /opt/iso-hub/secret/iso_hub_key
```

compose 里挂载该文件并改用 `ISO_HUB_SECRET_KEY_FILE`：

```yaml
    volumes:
      - ./secret:/secret:ro
    environment:
      - ISO_HUB_SECRET_KEY_FILE=/secret/iso_hub_key
```

> 注意：密钥文件必须存在且可读，否则变量解析为 None → 退化为明文（不报错，但等于没加密）。

### 验证是否生效

启用并重启、在面板改一次任意设置后，检查磁盘文件头（应为密文魔数 `ISOHUB-SETTINGS-ENC-v1`）：

```bash
head -c 24 /opt/iso-hub/data/settings.json; echo
```

## 自定义源自动刷新（面板配置，非环境变量）

**v1.1.6 起**，自定义"发行版源"的自动刷新开关与间隔**不是环境变量**，而是网页面板配置，持久化到 `data/settings.json`（键 `custom_source_auto_refresh` / `custom_source_refresh_interval`）。默认**关闭**，间隔默认 `86400` 秒（每天），最小 `60` 秒。可在自定义源面板或 `GET/POST /api/custom-sources/auto-refresh` 设置。相关 API：`POST /api/custom-sources/refresh`（手动刷新）、`GET/POST /api/custom-sources/auto-refresh`（自动刷新开关/间隔）。
