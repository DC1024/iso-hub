# 下载与元数据

## 基本流程

1. **抓取最新元数据**：点右上角「抓取最新版本元数据」（联网访问清华镜像站，把最新版本写入 `distributions.json`）。
2. **勾选**：在镜像列表勾选要下载的发行版/单个版本文件。
3. **下载**：点「下载」，后台顺序下载所选条目，实时日志 + 进度条。

## 下载做了什么

项目用自带 `web/iso_runner.py` 复用上游 `LinuxDistributionDownloader`，但**只下载所选条目**：

- **禁用自动清理**（避免误删同组未选文件）
- 下载前先 **HEAD 探测目标文件大小**（`#TARGET <path> <bytes>`），前端据此算进度百分比
- 下载完做 **SHA256 校验**（在线 checksum 优先，其次清单内置值），配了 `gpg_verify` 的发行版先验 checksum 文件的 GPG 签名
- 校验**明确不符**（拿到了官方摘要但比对不一致）才会丢弃重下；**校验源不可达**（404/超时/清单里没这个文件名）不再重下

## 「未验签」与「重新校验」

校验源不可达但文件长度与服务器声明一致时，文件会被**落定**（否则一个配错的 checksum 模板会导致每周重下整个 ISO），并在列表里显示 **⚠ 未验签** —— 它的意思是"这份文件可用，但这次落定没有任何 SHA256/GPG 证据"，而不是"下载失败"。

- 点该行的 **⟳** 按钮可**只对已下载的文件重新校验**：读盘算哈希 + 拉当前清单/验签，**不会重新下载**。校验在后台任务里跑（大文件可能几十秒），结束后徽标自动刷新。
- 校验通过 → 标记消失，恢复普通「已下载」。
- 校验不符 → 显示红色 **✕ 校验不符**：文件内容与当前官方清单不一致。可能是下载损坏，也可能是**上游用同名文件重新打包了新版**（Ubuntu/Debian 点版本常见）。**不会自动删文件**，是否重下由你决定。
- 仍然不可达 → 保持 ⚠，提示里会更新这次尝试的时间与原因。
- 该发行版**完全没配校验源**（`checksum_url` 与 `checksum` 都为空）时按钮会直接报错——没有校验源就无从校验，请先在「自定义源」里补上。

> 只校验模式也可在服务器上直接跑：`docker exec iso-hub python /app/web/iso_runner.py --json-file /data/distributions.json --download-dir /data --verify-only --rel linux/Ubuntu/xxx.iso`，退出码 `0`=通过、`3`=不符、`4`=无法判定。

## 元数据刷新（抓取最新版本）

运行 `update_distributions.py --config sources_config.json --output /data/distributions.json --pretty`：

- 请求清华镜像站目录
- 正则提取版本目录
- 组合下载/校验 URL
- 排序写入清单（每组默认保留**最新 3 个**版本）

> 想调整每组保留数量：改 `iso_download/sources_config.json` 里各 source 的 `max_entries`，然后重建镜像。

## 数据落盘位置

- 下载的 ISO：`./data/linux/{type}/{发行版}/{文件}`（例 `data/linux/Ubuntu/ubuntu-26.04-live-server-amd64.iso`）
- 清单：`./data/distributions.json`

## 手动刷元数据（服务器上）

```bash
docker exec iso-hub python /app/iso_download/update_distributions.py \
  --output /data/distributions.json --pretty
```

## 常见问题

- **同一时刻只允许一个任务**（下载或刷元数据互斥），UI 有任务进度条。
- **中断/停止任务**会留下不完整文件，下次下载该校验失败会自动覆盖重下。
- 下载报 `unrecognized arguments: "Arch"` 等解析错误？这是旧版 bug，**升级到 1.0.1+ 已修复**（cmd 以列表传给 argparse，不再 `.split(" ")` 拆坏 JSON 参数）。
