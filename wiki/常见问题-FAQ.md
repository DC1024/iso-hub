## A. 安装、启动与网络

### 9. 8899 端口公网访问不了

- 确认容器在跑：`docker compose ps`
- 确认云厂商**安全组 / 防火墙**放行了对应端口（Lighthouse / 腾讯云需在控制台放行）。
- 确认端口映射：`docker ps` 看 `0.0.0.0:8899->8080/tcp`。
- 用 `curl http://127.0.0.1:8899/api/health` 看容器内是否 ok。

### 14. 默认起了几个容器？为什么没有共享 / 种子功能

**默认只有 2 个**：`iso-hub`（Web 服务）+ `socket-proxy`（Docker API 白名单代理）。

samba / webdav 挂在 `share` profile、qbittorrent 挂在 `bt` profile —— **不带 `--profile`
就不会创建容器、不会拉镜像**。要启用：

```bash
docker compose --profile share up -d      # + SMB / WebDAV
docker compose --profile bt up -d         # + 种子下载
docker compose --profile share --profile bt up -d   # 都要
```

或写进 `.env` 一劳永逸：`COMPOSE_PROFILES=share,bt`。

> 这条被文档写错过两次（写成"三容器"/"四容器"），现在有 `test_wiki_deploy_doc.py` 盯着。

### 15. 容器起不来，日志里写「启动中止: 数据目录不可写」

v1.5.0 起容器以 **uid/gid 10001** 非 root 运行，且根文件系统只读。绑定挂载的属主由
**宿主机**决定，容器内改不了。宿主目录属主对不上时，启动自检会**立即退出**并打印可照抄的命令：

```bash
docker compose down
sudo chown -R 10001:10001 ./data ./backups ./qb-config ./webdav-config ./samba-config
docker compose up -d
```

**面板能打开但下载/删除都报 Permission denied** 是同一个根因（自检被绕过的老部署）。
另一个可能是 qBittorrent 仍以 root 写盘：`.env` 里 `QB_PUID` / `QB_PGID` 应为 `10001`。

`curl http://127.0.0.1:8899/api/health` 的 `writable` / `writable_states` 字段会直接标出
哪个挂载点写不了，并区分 `missing`（卷没挂）与 `denied`（属主不对）—— 两者的处置方式完全不同。

### 16. 前面挂了 Nginx / Traefik，登录和建号都不对劲

设 `ISO_HUB_TRUST_PROXY=1`，让后端从 `X-Forwarded-For` 取真实客户端 IP。

**没有反代时千万别开**：开了之后任何客户端都能自称 `127.0.0.1`，
"只允许内网建号"这道防线就没了。

反代本身需要转发的头：`Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`。
大文件下载建议把 `proxy_read_timeout` 调到 600s 以上。

## B. 账号与登录

### 7. 网页能开，但下载/操作没权限提示

检查是否触发了登录 / 令牌门禁：

- `ISO_HUB_REQUIRE_LOGIN=1`（默认）：必须登录管理员账号。
- `ISO_HUB_TOKEN` 已设置：所有写操作还需弹窗输入令牌。

### 8. 登录页提示「管理员账号未设置」

**现象**：从公网 `http://<服务器IP>:8899` 打开登录页，输入账号密码提交后报 HTTP 403，提示：

```text
管理员账号未设置, 请先在服务器本机或局域网内建号, 或设置 ISO_HUB_ADMIN_USER/PASS
```

**原因**：不是故障，是 `/api/user/login` 的**防抢注**逻辑。用户表为空且没设 `ISO_HUB_ADMIN_USER` 时，后端只放行**本机或私有网段**（`127.0.0.1` / `::1` / `10.x` / `172.16-31.x` / `192.168.x` / `fc00::/7` 等）的请求建号，公网来源一律 403——否则任何人都能抢先注册成管理员。

**三种解法**：

| 方式 | 做法 | 适合 |
|---|---|---|
| **A. 环境变量播种（推荐）** | compose 同目录 `.env` 写 `ISO_HUB_ADMIN_USER=admin` + `ISO_HUB_ADMIN_PASS=你的密码`，`chmod 600` 后 `docker compose up -d` | 公网部署 |
| **B. 局域网内直接建号** | 在同一局域网的电脑上打开 `http://<服务器内网IP>:8899`，首次登录即建号（v1.8.0 起不再要求必须是本机） | 内网 / NAS 部署 |
| **C. 本机首次登录建号** | `ssh -L 8899:127.0.0.1:8899 <user>@<服务器IP>`，浏览器开 <http://localhost:8899> 首次登录即建号 | 只能走 SSH 隧道 |

> **别把内网服务直接暴露到公网**：放宽到局域网的前提是"公网打不进来"。若把 8899 映射到公网且没设 `ISO_HUB_ADMIN_USER`，请在完成建号前先关掉端口映射。

完整步骤见 [快速部署 → 首次启动必做](部署-快速开始)。建号后公网即可正常登录；改密码走面板「设置 → 修改密码」（改 `.env` 重启无效）。

## C. 下载、校验与磁盘

### 1. 下载报错：`unrecognized arguments: "Arch", "download_url": ...`

**已修复（1.0.1+）**。这是旧版 bug：后端把命令拼成字符串后 `.split(" ")` 拆分，把带空格/逗号/引号的 JSON `--select` 参数拆坏成多个 argv，导致 argparse 报 unrecognized arguments。

- 现象：`iso_runner.py: error: unrecognized arguments: "Arch", "download_url": ...`
- 修复：命令以 **list** 传给 `subprocess.Popen`（不再字符串 split）。
- 解决：**升级到最新版本**（docker compose 重建）即可。

### 3. 下载没进度条

**已修复（1.0.1+）**。原因：后端 `/api/state` 的下载项缺少 `total` 字段，前端无法算百分比。

- 修复：下载前先 HEAD 探测目标文件大小（`#TARGET <path> <bytes>`），写入任务的 targets 映射，`running_task()` 据此给每项加 `total`，前端渲染进度条百分比。

### 4. 进度条卡在 0%，日志只在「停止任务」后才刷出

**已修复（1.0.2），本坑极隐蔽，务必升级。**

根因不是后端，而是**前端变量遮蔽**：`poll()` 里 `const t = s.task` 用局部变量 `t` **遮蔽了全局 i18n 翻译函数 `t()`**。后续 `t('taskMeta')` / `t('curPrefix')` 抛 `TypeError: t is not a function`，被外层 try/catch 静默吞掉 → 任务类型/当前文件/进度条全不更新；`fetchLogs()` 也被跳过，所以日志只有走「停止任务」else 分支时才刷出。

- 修复：poll() 内局部变量 `t` 改名 `tk`；同时修了 `applySrcTpl()` 里同样的遮蔽。
- 升级到 **1.0.2+** 后，实机验证进度条正常 2%→4%→…持续增长。

> 若在新版本上仍看到进度不动，大概率不是这个 bug：先看 [19](#19-下载被直接拒绝提示空间不足)
> 与「任务条显示的当前文件」是否已被已完成文件霸占（1.3.2 已修）。

### 18. 反复报「校验失败」，到底是镜像站的问题还是本地的问题

先分清两类错误 —— 它们现在会**分开报**（1.3.1 起）：

| 报错 | 含义 | 怎么办 |
|---|---|---|
| 「清单里没有这个文件」 | 该镜像站的 checksum 文件里查不到这个名字 | 换源，或等镜像站同步；不是本地问题 |
| 「内容确实不符」（带实际 SHA256） | 文件坏了或上游用同名文件重新打包 | 重下；若重下仍不符，多半是上游重新打包，去官网核对 |

历史上最坑的一次"镜像站背锅"其实是客户端 bug：下载期间文件叫 `xxx.iso.part`，而
`sha256sums.txt` 里登记的是 `xxx.iso`，老代码用**子串包含**判断，`"...iso.part"` 不是
`"...iso"` 的子串 → 永远匹配不上 → 报"所有校验和验证都失败"→ 半成品被当损坏丢弃。
1.3.1 已改为"剥离 `.part` 后缀 + 按空白切分精确比对文件名"。

**校验源不可达但长度达标**时，文件会带 **⚠ 未验签** 标记（可用，但没有证据）。
不必重下几个 GB：点该行的 **⟳ 重新校验**，只读盘算哈希（1.4.0 起）。

### 19. 下载被直接拒绝，提示空间不足

**这是特性，不是 bug（1.5.2 起）。** 写第一个字节之前会先算"这次要写多少"对比可用空间
（另留 256 MiB 余量），不足就直接拒单 —— 而不是下到 99% 才 `ENOSPC` 留一个 `.part`。

- **换源也没用**：写不下就是写不下，所以不会触发换源重试。
- **大小未知时放行**，但会在日志里明确告警。
- `disk_usage` 不可用（部分 FUSE / 网络盘）时 fail-open，不阻断下载。

清理空间的手段：镜像列表「清理过期」（列出不在最新清单里的旧文件）、
删掉「下载停止」的半成品、或调小订阅的保留版本数 N。

### 20. 点了「下载到本机」，浏览器没反应 / 下到一半断了

「下载到本机」走的是**短时票据**（默认 10 分钟），不是会话 token：

- 票据在有效期内**可重复使用**，所以断点续传和连接重试都没问题。
- 但如果**开了多个标签页隔了很久再点**，票据可能已过期 → 重新点一次即可（会换新票据）。
- 下载中断后浏览器若提示"无法续传"，通常是反代把 `Range` 头吃掉了；
  确认反代透传 `Range` 且未开启对大响应的缓冲。

## D. 界面状态与版本

### 2. 日间模式，任务日志部分文字看不清（颜色接近背景）

**已修复（1.0.0+）**。原因：日志面板背景固定深色，但普通 `<pre>` 文本继承了日间主题的深色 `--ink`，深字配深底看不清；夜间主题 `--ink` 是浅色所以正常。

- 修复：日志区内文本改为固定浅色（`#cbe3ff` / `#d7e7ff` / 时间戳 `#8fb6dd`），不再依赖主题变量。
- 若仍看不清：强制刷新（Ctrl+F5）确保加载新前端（看标题徽章版本号）。

### 5. 点「刷新列表」没反应，且分不清它和「抓取最新版本元数据」的区别

这是两个不同概念，都不是 bug：

- **刷新列表**：只**重读本地** `distributions.json` 到界面，**不联网**。用于后台任务完成后刷新展示。
- **抓取最新版本元数据**：**联网**访问清华镜像站，把**最新版本**写进清单（默认每组留最新 3 个）后再刷新列表。

1.2.8 起「刷新列表」成功会提示「列表已刷新 · MM-DD HH:MM」，点击瞬间按钮进入旋转 loading 态，
失败会明确报错（`刷新失败 (HTTP xxx)`），不再"点了没反应"。

若仍旧毫无反应：大概率是浏览器缓存了旧前端（徽章版本号偏旧）。**强制刷新**（Ctrl+F5）。

### 6. 顶部有两个「网络共享」，重复

**已修复（1.0.3）**。1.0.3 起删除顶部独立的「网络共享」标签页，网络共享统一并入**「设置 → 共享设置」**。功能一致（同一 `/api/shares` 后端）。

### 11. 怎么确认我加载的是最新前端

看标题右上角**版本徽章**，对照 GitHub Releases 的最新 tag。小于最新说明是缓存，**Ctrl+F5 强制刷新**。

更可靠的确认方式（1.8.3 起）：`curl -sI http://<IP>:8899/ | grep -i x-version` ——
这个响应头的值由 `web/version.py` 直接给出，不经过浏览器缓存。

### 12. 全站突然卡死 / 点什么都转圈不响应（waitress 线程耗尽）

**已修复（1.1.6）**。这是真实故障，根因是**请求线程内实时抓取网络**：

- 前端每 30s 无脑轮询 `/api/distros` → 后端每次在请求线程里**实时抓取自定义源目录** → CN 网络下部分镜像站 TLS 握手慢/挂死 → 8 个 waitress 线程全被占住 → 后续所有请求排队，全站卡死。
- **修复（1.1.6）**：`/api/distros` 请求线程**只读本地缓存** `custom_repo_cache.json`，**绝不再发网络请求**；自定义源展开改为后台子进程（`custom_repo_refresh.py`）手动/定时刷新落盘；`fetch_text` 加连接阶段 10s 硬超时；前端移除 30s 无脑轮询。
- **解决**：升级到 **1.1.6+**。升级后 `/api/distros` 应在毫秒级返回。

### 13. 自定义「发行版源」（strategy）在镜像列表里不显示

**非故障，是缓存机制（1.1.6 起）**。strategy 类型的发行版源要先"展开"成具体 ISO 条目，而展开结果走**持久化缓存**（`custom_repo_cache.json`），**首次手动刷新前缓存为空**，故列表里暂不出现。

- 在自定义源面板点「🔄 刷新发行版源」（`POST /api/custom-sources/refresh`）触发一次后台展开，成功写入缓存后即合入镜像列表。
- 或开启**自动定时刷新**（`GET/POST /api/custom-sources/auto-refresh`，默认关，间隔默认每天、最小 60s）。
- 刷新失败会保留缓存里的旧条目，不会清空已展示列表。普通直链自定义源不受此影响，添加后立即可见。

## E. 网络共享与外部服务

### 10. 挂载 SMB 失败（网络/服务都正常）

服务端 SMB 正常、端口通、但客户端挂载失败时，九成是**客户端填法**：

- **不要**带 `smb://` 前缀（很多挂载向导不认，协议是单独选的）。
- **拆字段**：服务器IP 单独一栏、端口单独一栏、共享名 `iso` 单独一栏。
- 只能填整体串时：`<IP>:1445/iso`。
- 服务器端快速验证：`smbclient //<IP>/iso -p 1445 -U 'iso2%pass' -c 'ls'`。

详见 [网络共享](网络共享-SMB-WebDAV)。

### 21. 共享开关打不开 / 提示「请先设置密码」

从 1.3.21 起**取消了内置默认口令** `iso123`。密码为空时后端直接拒绝启用共享 ——
这是刻意的：默认口令等于"部署完就有一个公开可读的共享"。

去「设置 → 共享设置」设密码（SMB 与 WebDAV 各一套），保存后 sidecar 会自动重启。
只想临时改端口的话，`.env` 里设 `SAMBA_PORT`，无冲突的机器可以设 `445`。

### 22. qBittorrent 显示「容器状态未知，请检查 socket-proxy」

先分清你在用哪种 qB：

| 场景 | 状态应显示 | 说明 |
|---|---|---|
| 内置 sidecar（`--profile bt`） | 运行 / 已停止 / 未部署 / 未知 | 四态需要 socket-proxy 可用来查容器状态 |
| **外部**自行部署的 qB | ● 已连接 / ✗ 用户名或密码错误 / ✗ 无法连接 | 只走 Web API 登录，**不需要** socket-proxy |

1.3.12 起外部 qB 显示真实探测结果，不再报"请检查 socket-proxy"（那条提示对外部实例毫无意义）。
若外部 qB 显示「无法连接」：核对地址是否带协议（`http://`）、端口、以及跨主机网络可达性。

## F. 升级、时区与数据

### 23. 升级会不会丢数据 / 配置

不会。所有状态都在宿主机的挂载卷里（`./data`、`./backups` 等），镜像是无状态的。

标准升级：

```bash
docker compose pull
docker compose up -d
```

**注意两点**：

1. **跨 v1.4.x → v1.5.0+ 是 breaking change**，必须先 `chown -R 10001:10001` 那几个目录，
   见 [15](#15-容器起不来日志里写启动中止-数据目录不可写)。
2. **不要用 `--force-recreate` 重建正在下载的 recorder 类容器** —— 本项目没有这问题，
   但如果你同时跑了别的服务，注意 `up -d` 的连带重建。

升级前想留个后路：`docker exec iso-hub python /app/scripts/backup.py`，
备份产物在 `./backups`，恢复见 [备份与恢复](备份与恢复)。

### 24. 时区不对 / 定时任务在错误的时间触发

设 `.env` 里的 `TZ=Asia/Shanghai`（默认就是），然后 `docker compose up -d` 让容器重建。
只 `restart` 不重建时，环境变量不会更新。

定时任务的时间按**容器本地时间**解释，所以 `TZ` 不对会让"每天 02:30"跑到别的时间点。

### 25. 想把 flat 改成 classified（或反过来），已下载的文件会动吗

**不会。** 存放模式（`ISO_HUB_STORAGE_MODE` 或「设置 → 存放模式」）**只影响之后的下载**，
已有文件原地不动。

两种布局：

```text
classified:  data/linux/<发行版>/<文件>      例: data/linux/Ubuntu/ubuntu-24.04.iso
flat:        data/iso/<文件>                 例: data/iso/ubuntu-24.04.iso
```

切换后旧文件在列表里仍能被识别（后端两种布局都扫），但**不会自动搬家**。
